### 🚀 Quick Commands

```bash
# Подключение к FTP-серверу
ftp <TARGET_IP>

# Рекурсивное скачивание всех файлов и каталогов через анонимный доступ
wget -m --no-passive ftp://anonymous:anonymous@<TARGET_IP>

# Сканирование FTP-сервиса с использованием стандартных скриптов NSE и определением версии
sudo nmap -sV -p21 -sC -A <TARGET_IP>

# Обновление базы данных скриптов Nmap
sudo nmap --script-updatedb

# Поиск всех доступных NSE-скриптов для FTP
find / -type f -name "ftp*" 2>/dev/null | grep scripts

# Сканирование с трассировкой скриптов для анализа взаимодействия на сетевом уровне
sudo nmap -sV -p21 -sC -A <TARGET_IP> --script-trace

# Взаимодействие с сервисом через netcat
nc -nv <TARGET_IP> 21

# Взаимодействие с сервисом через telnet
telnet <TARGET_IP> 21

# Установка защищенного соединения и просмотр SSL-сертификата
openssl s_client -connect <TARGET_IP>:21 -starttls ftp
```

**Service Interaction (внутри FTP/TFTP)**
```bash
# Аутентификация под анонимным пользователем
anonymous

# Просмотр текущего статуса и конфигурации сессии
status

# Включение режима отладки для просмотра ответов сервера
debug

# Включение трассировки пакетов
trace

# Рекурсивный вывод содержимого каталогов (если разрешено)
ls -R

# Скачивание файла
get <FILE>

# Загрузка локального файла на сервер
put <FILE>

# Выход из сессии
quit
```

### 🛠 Tools & Utilities

- `[[ftp]]` — Стандартный клиент для взаимодействия с FTP-серверами.

- `[[openssl]]` — Используется для анализа SSL/TLS сертификатов на защищенных FTP-соединениях.

### 📝 Technical Analysis & Media

> [!info] Принципы работы FTP
> FTP (File Transfer Protocol) работает на прикладном уровне стека TCP/IP. Для работы используются два канала:
> 1. **Управляющий канал (TCP 21):** Передача команд и кодов состояния.
> 2. **Канал передачи данных (TCP 20):** Используется исключительно для передачи файлов.
> 
> **Режимы работы:**
> - **Active FTP:** Клиент открывает порт и ждет соединения от сервера. Часто блокируется брандмауэрами клиента.
> - **Passive FTP:** Сервер объявляет порт, к которому должен подключиться клиент. Это предпочтительный метод для обхода брандмауэров.

#### TFTP (Trivial File Transfer Protocol)
TFTP значительно проще FTP. Он использует **UDP** и не поддерживает аутентификацию. Доступ к файлам ограничивается только правами доступа в самой ОС. Из-за отсутствия безопасности TFTP обычно используется только в локальных защищенных сетях для загрузки конфигураций сетевого оборудования или бездисковых станций.

#### Конфигурация vsFTPd
Один из самых популярных FTP-серверов в Linux — `vsFTPd`. Его основной конфигурационный файл находится по пути `/etc/vsftpd.conf`.

> [!example] Анализ /etc/vsftpd.conf
> ```bash
> MuraMitchi@htb[/htb]$ cat /etc/vsftpd.conf | grep -v "#"
> ```
> | Параметр | Описание |
> | --- | --- |
> | `listen=NO` | Запускать из inetd или как отдельный демон? |
> | `listen_ipv6=YES` | Слушать по протоколу IPv6? |
> | `anonymous_enable=NO` | Разрешить анонимный доступ? |
> | `local_enable=YES` | Разрешить вход локальным пользователям? |
> | `dirmessage_enable=YES` | Отображать сообщения при переходе в каталоги? |
> | `use_localtime=YES` | Использовать местное время? |
> | `xferlog_enable=YES` | Включить регистрацию загрузок/скачиваний? |
> | `connect_from_port_20=YES` | Подключиться через порт 20? |
> | `secure_chroot_dir=/var/run/vsftpd/empty` | Пустая директория для chroot |
> | `pam_service_name=vsftpd` | Имя службы PAM для аутентификации |
> | `rsa_cert_file=/etc/ssl/certs/ssl-cert-snakeoil.pem` | Путь к сертификату RSA для SSL |
> | `rsa_private_key_file=/etc/ssl/private/ssl-cert-snakeoil.key` | Путь к приватному ключу RSA |
> | `ssl_enable=NO` | Включено ли SSL-шифрование? |

Также критически важным является файл `/etc/ftpusers`, содержащий список пользователей, которым **запрещен** доступ к FTP.

> [!example] Содержимое /etc/ftpusers
> ```bash
> MuraMitchi@htb[/htb]$ cat /etc/ftpusers
> guest
> john
> kevin
> ```

### 🔍 Command Breakdown (Deep Dive)

| Команда/Флаг | Описание | Зачем это для CPTS |
| --- | --- | --- |
| `ftp> debug` | Включает подробный вывод команд протокола. | Позволяет видеть сырые ответы сервера и скрытые сообщения. |
| `ftp> ls -R` | Рекурсивный листинг файлов (если `ls_recurse_enable=YES`). | Быстрое обнаружение всех файлов в глубоких структурах папок. |
| `wget -m` | Зеркалирование (mirror) всего FTP ресурса. | Автоматизирует сбор всех данных для последующего офлайн-анализа. |
| `nmap --script-trace` | Показывает каждый отправленный и полученный пакет скрипта NSE. | Помогает понять, почему скрипт не сработал или как именно он обнаружил уязвимость. |
| `tftp> get` | Скачивание файла через UDP без авторизации. | Позволяет вытягивать конфиги, если мы знаем их точное имя. |

### ⚠️ Vulnerable Configurations (Critical)

> [!warning] Опасные настройки FTP
> Перечисленные ниже параметры в `vsftpd.conf` делают сервер крайне уязвимым:
> 
> 1. `anonymous_enable=YES`: Позволяет любому пользователю войти в систему без учетной записи.
> 2. `anon_upload_enable=YES`: Анонимы могут загружать файлы. В сочетании с веб-сервером это ведет к **Web Shell/RCE**.
> 3. `anon_mkdir_write_enable=YES`: Позволяет анонимам создавать папки, что может быть использовано для дефейса или хранения вредоносного ПО.
> 4. `write_enable=YES`: Глобальное разрешение на команды записи (STOR, DELE и др.).
> 5. `ls_recurse_enable=YES`: Облегчает злоумышленнику поиск чувствительных данных по всей структуре каталогов.

### 💡 Pentest Insights

> [!tip] Хакерские хитрости
> - **Анализ баннеров:** Код ответа `220` часто содержит версию сервера (например, `vsFTPd 2.3.4`), которая может иметь известные эксплойты (backdoor).
> - **Скрытие ID:** Если включено `hide_ids=YES`, все владельцы файлов отображаются как `ftp`. Это защита от раскрытия имен пользователей ОС.
> - **SSL OSINT:** Используя `openssl s_client`, вы можете извлечь из сертификата `hostname`, `email` администратора и название организации. Это критически важные данные для атак типа Phishing или Password Spraying.
> - **LFI + FTP:** Если на сервере есть LFI, вы можете загрузить через FTP файл с PHP-кодом, а затем исполнить его, обратившись к нему через уязвимый веб-параметр.
