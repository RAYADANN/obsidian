# Network File System (NFS)

`Network File System` (`NFS`) — это сетевая файловая система, разработанная Sun Microsystems. Её назначение аналогично SMB: предоставление доступа к файловым системам по сети так, будто они являются локальными. NFS преимущественно используется в средах Linux и Unix. В отличие от ранних версий, где аутентифицировался только хост (`NFSv3`), современная версия `NFSv4` поддерживает аутентификацию пользователей, аналогично Windows SMB.

### 🚀 Quick Commands

#### OS Terminal
```bash
# Быстрое сканирование портов NFS и RPC
sudo nmap <TARGET_IP> -p111,2049 -sV -sC

# Поиск путей экспорта (доступных директорий) через nfs-showmount
showmount -e <TARGET_IP>

# Использование специализированных скриптов Nmap для перечисления содержимого
sudo nmap --script nfs* <TARGET_IP> -sV -p111,2049

# Создание точки монтирования и подключение удаленного ресурса
mkdir target-NFS && sudo mount -t nfs <TARGET_IP>:/ ./target-NFS/ -o nolock

# Просмотр содержимого с числовыми значениями UID и GID
ls -n ./target-NFS/mnt/nfs/

# Размонтирование ресурса после завершения работы
sudo umount ./target-NFS
```

### 🛠 Tools & Utilities

- `[[Nmap]]` — используется для сканирования портов и запуска NSE-скриптов (`nfs-ls`, `nfs-showmount`, `nfs-statfs`).
- `[[rpcinfo]]` — утилита для получения списка активных RPC-служб и их портов.
- `[[showmount]]` — инструмент для запроса списка экспортируемых файловых систем у демона `mountd`.
- `[[mount]]` — системная утилита для подключения (монтирования) удаленных ресурсов в локальную файловую систему.

### 📝 Technical Analysis & Media

#### Порты и Службы

| Порт | Протокол | Служба | Роль |
| :--- | :--- | :--- | :--- |
| **111** | TCP/UDP | `RPCbind` | Маппинг RPC-служб на конкретные порты (Portmapper). |
| **2049** | TCP/UDP | `NFS` | Основной порт для передачи данных (начиная с NFSv4 используется только он). |
| **Variable** | TCP/UDP | `mountd` | Обработка запросов на монтирование (в версиях до v4). |

> [!info] Теория: Версии NFS и механизмы работы
> - **NFSv2**: Устаревшая версия, работавшая изначально по UDP.
> - **NFSv3**: Поддерживает файлы переменного размера, улучшенную обработку ошибок. Не полностью совместима с v2.
> - **NFSv4**: Современный стандарт. Включает поддержку **Kerberos**, работу через Firewall (нужен только порт 2049), поддержку ACL и является протоколом с состоянием (stateful).
> - **NFSv4.1**: Добавляет поддержку кластерных серверов (pNFS) и многоканальный доступ (session trunking).
> 
> **RPC (Remote Procedure Call)**: NFS базируется на протоколе `ONC-RPC` (порт 111). Аутентификация в NFS часто делегируется параметрам RPC. Сервер доверяет параметрам `UID`/`GID`, передаваемым клиентом, что делает систему уязвимой в недоверенных сетях.

#### Конфигурация: /etc/exports

Файл `/etc/exports` определяет, какие директории доступны клиентам и с какими правами.

> [!example] Содержимое /etc/exports
> ```bash
> MuraMitchi@htb[/htb]$ cat /etc/exports
> # /etc/exports: the access control list for filesystems which may be exported
> #               to NFS clients. See exports(5).
> 
> # Example for NFSv2 and NFSv3:
> # /srv/homes       hostname1(rw,sync,no_subtree_check) hostname2(ro,sync,no_subtree_check)
> 
> # Example for NFSv4:
> # /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt,no_subtree_check)
> # /srv/nfs4/homes  gss/krb5i(rw,sync,no_subtree_check)
> ```

**Разбор параметров конфигурации:**

| Вариант | Описание |
| :--- | :--- |
| `rw` | Разрешено чтение и запись. |
| `ro` | Только чтение. |
| `sync` | Синхронная передача данных (подтверждение после записи на диск). |
| `async` | Асинхронная передача (быстрее, данные сначала попадают в кэш). |
| `secure` | Требует, чтобы запросы исходили с портов ниже 1024. |
| `insecure` | Разрешает использование портов выше 1024. |
| `no_subtree_check` | Отключает проверку того, является ли файл частью поддерева в экспортируемой директории. |
| `root_squash` | **Важно!** Сопоставляет запросы от `root` (UID 0) к анонимному пользователю (`nobody`). Это мешает злоумышленнику получить права root на сервере через монтирование. |

### 🔍 Command Breakdown (Deep Dive)

| Команда / Флаг | Описание | Зачем это для CPTS |
| :--- | :--- | :--- |
| `showmount -e` | Запрашивает список ресурсов. | Определение векторов атаки и доступных сетевых папок. |
| `mount -o nolock` | Монтирование без использования блокировки файлов. | Помогает избежать проблем с подключением к старым или специфичным конфигурациям NFS. |
| `ls -n` | Вывод списка файлов с числовыми UID/GID. | Критично для понимания, под каким именно ID нужно создать локального пользователя для обхода прав доступа. |
| `nfs-ls` (NSE) | Рекурсивный листинг файлов через Nmap. | Быстрое обнаружение чувствительных данных (SSH ключи, конфиги) без монтирования. |

### ⚠️ Vulnerable Configurations (Critical)

> [!warning] Опасные настройки NFS
> 
> - **`no_root_squash`**: Если этот параметр включен, то пользователь, имеющий права `root` на своей атакующей машине, при монтировании ресурса будет обладать правами `root` и на удаленной файловой системе. 
>     - **Вектор:** Злоумышленник может создать SUID-бинарник (например, копию `/bin/bash`) на смонтированном ресурсе, что позволит любому пользователю на целевом сервере получить root-права.
> - **`rw`**: Позволяет изменять файлы. В сочетании с плохими правами доступа к файлам внутри папки ведет к перезаписи конфигов или краже данных.
> - **`insecure`**: Позволяет клиентам подключаться с портов выше 1024. Это упрощает атаку, так как для создания сокета не требуются права root на стороне атакующего.

### 💡 Pentest Insights

> [!tip] Хакерские хитрости
> - **UID/GID Manipulation**: Если вы видите файл, принадлежащий UID 1001, к которому у вас нет доступа, просто создайте локального пользователя с этим UID на своей Kali (`useradd -u 1001 pentester`). NFS сервер доверяет вашему UID.
> - **SSH Key Theft**: Часто в NFS-шарах забывают директории `.ssh`. Проверяйте наличие `id_rsa`.
> - **SUID Binary**: Если `no_root_squash` активен, скопируйте `/bin/bash` на шару и установите SUID бит: `chmod +s bash`. Запустите его на целевом сервере для повышения привилегий.
> - **Сканирование RPC**: Всегда начинайте с `rpcinfo -p <IP>`, чтобы увидеть, какие еще службы (кроме NFS) висят на RPC (например, `nlockmgr`, `status`).
