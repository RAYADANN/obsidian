R-сервисы — это набор сервисов, предназначенных для обеспечения удалённого доступа или выполнения команд между хостами Unix по протоколу TCP/IP. Первоначально разработанные исследовательской группой компьютерных систем (CMS `CSRG`) Калифорнийского университета в Беркли, `r-services`они были де-факто стандартом для удалённого доступа между операционными системами Unix, пока их не заменили `SSH`протоколы и команды Secure Shell (SSL) из-за присущих им уязвимостей безопасности. Подобно SSL `telnet`, R-сервисы передают информацию от клиента к серверу (и наоборот) по сети в незашифрованном формате, что позволяет злоумышленникам перехватывать сетевой трафик (пароли, информацию для входа в систему и т. д.) путём проведения атак типа «человек посередине» (DWD `MITM`).

`R-services`Они охватывают порты `512`, `513`, и `514`и доступны только через набор программ, известных как `r-commands`. Чаще всего они используются коммерческими операционными системами, такими как Solaris, HP-UX и AIX. Хотя в настоящее время они встречаются реже, мы время от времени сталкиваемся с ними во время наших внутренних тестов на проникновение, поэтому стоит понимать, как к ним подходить.

Пакет [команд R](https://en.wikipedia.org/wiki/Berkeley_r-commands) состоит из следующих программ:

- rcp ( `remote copy`)
- рексек ( `remote execution`)
- рлогин ( `remote login`)
- рш ( `remote shell`)
- рстат
- время разрыва
- рво ( `remote who`)

Каждая команда имеет свою предназначенную функциональность; однако мы рассмотрим только наиболее часто используемые `r-commands`. В таблице ниже представлен краткий обзор наиболее часто используемых команд, включая службу-демон, с которой они взаимодействуют, порт и метод передачи данных, а также краткое описание каждой из них.

|**Командование**|**Сервисный демон**|**Порт**|**Транспортный протокол**|**Описание**|
|---|---|---|---|---|
|`rcp`|`rshd`|514|TCP|Копирование файла или каталога в обоих направлениях с локальной системы на удаленную (или наоборот) или с одной удаленной системы на другую. Работает аналогично команде `cp`в Linux, но предоставляет `no warning to the user for overwriting existing files on a system`.|
|`rsh`|`rshd`|514|TCP|Открывает командную оболочку на удалённом компьютере без процедуры входа в систему. Для проверки использует доверенные записи в файлах `/etc/hosts.equiv`и .`.rhosts`|
|`rexec`|`rexecd`|512|TCP|Позволяет пользователю выполнять команды оболочки на удалённой машине. Требует аутентификации с помощью `username`и `password`через незашифрованный сетевой сокет. Аутентификация переопределяется доверенными записями в файлах `/etc/hosts.equiv`и `.rhosts`.|
|`rlogin`|`rlogind`|513|TCP|Позволяет пользователю войти на удаленный хост по сети. Работает аналогично, `telnet`но может подключаться только к Unix-подобным хостам. Аутентификация переопределяется доверенными записями в файлах `/etc/hosts.equiv`и `.rhosts`.|

Файл /etc/hosts.equiv содержит список доверенных хостов и используется для предоставления доступа другим системам в сети. Когда пользователи на одном из этих хостов пытаются получить доступ к системе, им автоматически предоставляется доступ без дополнительной аутентификации.

`MuraMitchi@htb[/htb]$ cat /etc/hosts.equiv # <hostname> <local username> pwnbox cry0l1t3`

#### Контроль доступа и доверительные отношения

Основная проблема `r-services`, и одна из главных причин `SSH`его замены, заключается в присущих этим протоколам проблемах с контролем доступа. R-сервисы полагаются на доверенную информацию, отправляемую удаленным клиентом на хост-машину, к которой они пытаются аутентифицироваться. По умолчанию эти сервисы используют [подключаемые модули аутентификации (PAM)](https://debathena.mit.edu/trac/wiki/PAM) для аутентификации пользователей в удаленной системе; однако они также обходят эту аутентификацию, используя файлы `/etc/hosts.equiv`и `.rhosts`в системе. Файлы `hosts.equiv`и `.rhosts`содержат список хостов ( `IPs`или `Hostnames`) и пользователей, которые находятся `trusted`на локальном хосте при попытке подключения с помощью `r-commands`. Записи в любом из файлов могут выглядеть следующим образом:

**Примечание:** данный `hosts.equiv`файл рассматривается как глобальная конфигурация для всех пользователей в системе, тогда как другой файл `.rhosts`предоставляет конфигурацию для каждого пользователя отдельно.

#### Пример файла .rhosts

        shellsession
`MuraMitchi@htb[/htb]$ cat .rhosts htb-student     10.0.17.5 +               10.0.17.10 +               +`

Как видно из этого примера, оба файла используют специфический синтаксис пар `<username> <ip address>`«или `<username> <hostname>`». Кроме того, `+`модификатор можно использовать в этих файлах в качестве подстановочного знака для указания чего угодно. В этом примере модификатор `+`позволяет любому внешнему пользователю получать доступ к командам r из `htb-student`учетной записи пользователя через хост с IP-адресом `10.0.17.10`.

Неправильные настройки в любом из этих файлов могут позволить злоумышленнику аутентифицироваться как другой пользователь без учетных данных, что потенциально может привести к выполнению кода. Теперь, когда мы понимаем, как можно злоупотреблять неправильными настройками в этих файлах, давайте попробуем войти на целевой хост, используя `rlogin`.

#### Вход в систему с помощью Rlogin

        shellsession
`MuraMitchi@htb[/htb]$ rlogin 10.0.17.2 -l htb-student Last login: Fri Dec  2 16:11:21 from localhost [htb-student@localhost ~]$`

Благодаря ошибкам в файле конфигурации нам удалось успешно войти в систему под `htb-student`учетной записью на удаленном хосте `.rhosts`. После успешного входа в систему мы также можем использовать `rwho`команду для вывода списка всех интерактивных сессий в локальной сети, отправляя запросы на UDP-порт 513.

#### Отображение списка авторизованных пользователей с помощью Rwho

        shellsession
`MuraMitchi@htb[/htb]$ rwho root     web01:pts/0 Dec  2 21:34 htb-student     workstn01:tty1  Dec  2 19:57  2:25`

Из этой информации видно, что `htb-student`пользователь в данный момент аутентифицирован на `workstn01`хосте, тогда как `root`пользователь аутентифицирован на `web01`хосте. Мы можем использовать это в своих интересах при определении потенциальных имен пользователей для дальнейших атак на хосты в сети. Однако `rwho`демон периодически передает информацию о вошедших в систему пользователях, поэтому может быть полезно отслеживать сетевой трафик.

#### Отображение списка авторизованных пользователей с помощью Rusers

Для предоставления дополнительной информации в сочетании с командой `rwho`можно выполнить `rusers`команду. Это позволит получить более подробный отчет обо всех пользователях, вошедших в систему по сети, включая такую ​​информацию, как имя пользователя, имя хоста доступной машины, терминал (TTY), к которому пользователь подключен, дата и время входа пользователя, время, прошедшее с момента ввода текста на клавиатуре, и удаленный хост, с которого был выполнен вход (если применимо).

        shellsession
`MuraMitchi@htb[/htb]$ rusers -al 10.0.17.5 htb-student     10.0.17.5:console          Dec 2 19:57     2:25`

Как мы видим, R-сервисы сегодня используются реже из-за присущих им недостатков в области безопасности и наличия более защищенных протоколов, таких как SSH. Чтобы быть всесторонне развитым специалистом по информационной безопасности, необходимо обладать широким и глубоким пониманием множества систем, приложений, протоколов и т. д. Поэтому запомните эти знания о R-сервисах, потому что вы никогда не знаете, когда можете с ними столкнуться.
