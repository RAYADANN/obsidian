[Rsync](https://linux.die.net/man/1/rsync) — это быстрый и эффективный инструмент для локального и удалённого копирования файлов. Он может использоваться для копирования файлов локально на заданном компьютере, а также на/с удалённых хостов. Он очень универсален и известен своим алгоритмом дельта-передачи. Этот алгоритм уменьшает объём данных, передаваемых по сети, если версия файла уже существует на целевом хосте. Он делает это, отправляя только различия между исходными файлами и более старой версией файлов, находящейся на целевом сервере. Он часто используется для резервного копирования и зеркалирования. Он находит файлы, которые необходимо передать, анализируя файлы, размер которых изменился, или время последнего изменения. По умолчанию он использует порт `873`и может быть настроен на использование SSH для безопасной передачи файлов, используя установленное SSH-соединение с сервером.

В этом [руководстве](https://book.hacktricks.xyz/network-services-pentesting/873-pentesting-rsync) рассматриваются некоторые способы злоупотребления Rsync, в первую очередь, путем получения списка содержимого общей папки на целевом сервере и извлечения файлов. Иногда это можно сделать без аутентификации. В других случаях нам потребуются учетные данные. Если вы обнаружите учетные данные во время тестирования на проникновение и столкнетесь с Rsync на внутреннем (или внешнем) хосте, всегда стоит проверить, не используются ли повторно пароли, поскольку вы можете получить доступ к конфиденциальным файлам, которые могут быть использованы для получения удаленного доступа к целевому серверу.

Давайте быстро проверим, что происходит. Мы видим, что Rsync используется по протоколу 31.

#### Поиск доступных акций

Далее мы можем немного изучить этот сервис, чтобы посмотреть, к чему мы сможем получить доступ.

        shellsession
`MuraMitchi@htb[/htb]$ nc -nv 127.0.0.1 873 (UNKNOWN) [127.0.0.1] 873 (rsync) open @RSYNCD: 31.0 @RSYNCD: 31.0 #list dev             Dev Tools @RSYNCD: EXIT`

#### Перечисление открытых акций

Здесь мы видим долю под названием `dev`, и мы можем продолжить ее перечисление.

        shellsession
`MuraMitchi@htb[/htb]$ rsync -av --list-only rsync://127.0.0.1/dev receiving incremental file list drwxr-xr-x             48 2022/09/19 09:43:10 . -rw-r--r--              0 2022/09/19 09:34:50 build.sh -rw-r--r--              0 2022/09/19 09:36:02 secrets.yaml drwx------             54 2022/09/19 09:43:10 .ssh sent 25 bytes  received 221 bytes  492.00 bytes/sec total size is 0  speedup is 0.00`

Из приведенного выше вывода видно несколько интересных файлов, которые, возможно, стоит загрузить для дальнейшего исследования. Также видно, что доступен каталог, предположительно содержащий SSH-ключи. Отсюда мы можем синхронизировать все файлы с нашим хостом атаки с помощью команды `rsync -av rsync://127.0.0.1/dev`. Если Rsync настроен на использование SSH для передачи файлов, мы можем изменить наши команды, добавив `-e ssh`флаг или, `-e "ssh -p2222"`если используется нестандартный порт для SSH. Это [руководство](https://phoenixnap.com/kb/how-to-rsync-over-ssh) поможет понять синтаксис использования Rsync через SSH.
