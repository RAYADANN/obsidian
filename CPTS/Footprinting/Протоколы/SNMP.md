### 1. 🚀 Quick Commands

**OS Terminal**
```bash
# Перечисление SNMP с использованием конкретной строки сообщества и версии 2c
snmpwalk -v2c -c <COMMUNITY_STRING> <TARGET_IP>

# Брутфорс строк сообщества (Community Strings) по списку слов
onesixtyone -c <WORDLIST> <TARGET_IP>

# Массовый опрос OID через braa (рекурсивный обход дерева .1.3.6.*)
braa <COMMUNITY_STRING>@<TARGET_IP>:.1.3.6.*

# Запрос конкретного OID (системное описание)
snmpwalk -v2c -c <COMMUNITY_STRING> <TARGET_IP> .1.3.6.1.2.1.1.1.0

# Генерация кастомного списка слов для строк сообщества (пример через crunch)
crunch 4 6 abcd123 -o snmp_wordlist.txt
```

---

### 2. 🛠 Tools & Utilities

- `[[snmpwalk]]` — стандартная утилита для выполнения запросов к SNMP-агенту и обхода дерева MIB.
- `[[onesixtyone]]` — высокопроизводительный сканер для поиска строк сообщества SNMP методом перебора.
- `[[braa]]` — инструмент для массового опроса SNMP-объектов, позволяющий эффективно выкачивать данные из конкретных веток OID.
- `[[crunch]]` — генератор словарей, полезный для создания списков потенциальных строк сообщества на основе известных шаблонов именования.

### 3. 📝 Technical Analysis & Media

#### Порты и Службы
| Порт | Протокол | Служба | Роль |
| :--- | :--- | :--- | :--- |
| 161 | UDP | SNMP Agent | Прием команд управления и запросов данных (Control/Query) |
| 162 | UDP | SNMP Traps | Прием уведомлений о событиях от агента к менеджеру (Unsolicited) |

> [!info] Теория и Принципы: SNMP Architecture
> `SNMP` (Simple Network Management Protocol) предназначен для мониторинга и управления сетевыми устройствами (маршрутизаторы, коммутаторы, серверы, IoT).
> - **MIB (Management Information Base):** Текстовый файл (ASCII, формат ASN.1), представляющий собой базу данных доступных объектов устройства в виде древовидной иерархии. MIB не содержит данных, а лишь описывает, "что" и "где" можно запросить.
> - **OID (Object Identifier):** Уникальный адрес узла в дереве MIB, состоящий из последовательности целых чисел (например, `.1.3.6.1.2.1.1.1.0`). Чем длиннее цепочка, тем специфичнее информация.
> - **Traps:** В отличие от стандартного опроса, "ловушки" позволяют серверу самому отправлять данные клиенту при наступлении события без явного запроса.

### 4. 🔍 Command Breakdown (Deep Dive)

| Команда/Флаг | Описание | Зачем это для CPTS |
| :--- | :--- | :--- |
| `snmpwalk -v2c` | Использование версии 2c (на базе community strings). | Самая частая версия в реальных сетях из-за простоты настройки. |
| `-c <string>` | Указание строки сообщества (пароля). | Позволяет авторизоваться для чтения или записи данных. |
| `onesixtyone -c` | Путь к словарю для брутфорса. | Идентификация скрытых или нестандартных строк сообщества. |
| `braa <str>@<IP>:<OID>` | Рекурсивный запрос через braa. | Скорость. Позволяет мгновенно выкачать огромные ветки данных (например, список ПО или сетевые интерфейсы). |

### 5. ⚠️ Vulnerable Configurations & Flaws (Critical)

> [!warning] Критические уязвимости и опасные настройки
> 1. **Отсутствие шифрования (v1, v2c):** Протоколы передают данные и **Community Strings** в открытом виде (clear-text). Злоумышленник может перехватить трафик (MITM) и получить пароли для управления сетью.
> 2. **Слабая аутентификация (v1, v2c):** Любой, кто знает или угадает строку сообщества, получает доступ к данным.
> 3. **Опасные параметры в `snmpd.conf`:**
>    - `rwuser noauth`: Полный доступ на чтение/запись ко всему дереву OID без какой-либо проверки подлинности.
>    - `rwcommunity <string> <IP>`: Предоставляет права на изменение конфигурации устройства любому, кто использует указанную строку (часто `private` или `admin`).
>    - `rwcommunity6`: Аналогично `rwcommunity`, но для IPv6-адресов.
> 4. **Информационная избыточность:** Через SNMP можно узнать версии ядра, установленные пакеты (например, `proftpd`), параметры загрузки (BOOT_IMAGE), контакты администратора и системные пути.

### 6. 💡 Pentest Insights

> [!tip] Хакерские хитрости
> - **Шаблоны именования:** В крупных сетях строки сообщества часто соответствуют именам хостов или их функциям. Если вы нашли строку `public` на одном сервере, попробуйте `public_<hostname>` или `snmp_<department>` на других.
> - **OSINT & SSL:** Если SNMP закрыт, но вы нашли SSL-сертификаты или баннеры других служб, используйте эти данные (названия компаний, имена админов) для генерации словаря строк сообщества через `crunch`.
> - **Рекурсивный поиск данных:** Всегда проверяйте ветку `.1.3.6.1.2.1.25` (Host Resources MIB). Там часто хранятся списки запущенных процессов, установленного ПО и параметры памяти, что критично для поиска векторов эксплуатации.
