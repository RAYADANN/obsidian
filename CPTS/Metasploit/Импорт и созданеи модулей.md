Чтобы установить новые модули Metasploit, уже портированные другими пользователями, можно обновить их `msfconsole`через терминал. Это гарантирует установку всех новейших эксплойтов, вспомогательных файлов и функций в последней версии `msfconsole`. Если портированные модули были добавлены в основную ветку Metasploit-framework на GitHub, то обновление должно обеспечить установку последних версий модулей.

Однако, если нам нужен только конкретный модуль и мы не хотим выполнять полное обновление, мы можем загрузить этот модуль и установить его вручную. Мы сосредоточимся на поиске в ExploitDB готовых модулей Metasploit, которые мы можем напрямую импортировать в нашу `msfconsole`локальную версию.

[ExploitDB](https://www.exploit-db.com/) — отличный выбор при поиске пользовательских эксплойтов. Мы можем использовать теги для поиска различных сценариев эксплуатации для каждого доступного скрипта. Один из таких тегов — [Metasploit Framework (MSF)](https://www.exploit-db.com/?tag=3) , который, если его выбрать, будет отображать только скрипты, также доступные в формате модулей Metasploit. Их можно напрямую загрузить из ExploitDB и установить в локальный каталог Metasploit Framework, откуда их можно искать и вызывать из `msfconsole`.

## Перенос скриптов в модули Metasploit

Для адаптации пользовательского скрипта эксплойта на Python, PHP или любом другом языке к модулю Ruby для Metasploit нам потребуется изучить язык программирования Ruby. Обратите внимание, что модули Ruby для Metasploit всегда пишутся с использованием жестовых табуляций.

Приступая к проекту по переносу кода, нам не нужно начинать кодирование с нуля. Вместо этого мы можем взять один из существующих модулей эксплойтов из категории, к которой относится наш проект, и адаптировать его для нашего текущего скрипта переноса. Важно всегда поддерживать порядок в пользовательских модулях, чтобы мы и другие специалисты по тестированию на проникновение могли использовать чистую и организованную среду при поиске пользовательских модулей.

Начнём с выбора кода эксплойта для переноса в Metasploit. В этом примере мы выберем [Bludit 3.9.2 — обход защиты от перебора паролей при аутентификации](https://www.exploit-db.com/exploits/48746) . Нам нужно будет скачать скрипт `48746.rb`и скопировать его в `/usr/share/metasploit-framework/modules/exploits/linux/http/`папку. Если мы загрузимся `msfconsole`прямо сейчас, то в той же папке, что и выше, мы найдём только один `Bludit CMS`эксплойт, что подтверждает, что наш эксплойт ещё не был перенесён. Хорошая новость в том, что в этой папке уже есть эксплойт Bludit, потому что мы будем использовать его в качестве шаблонного кода для нашего нового эксплойта.

## Написание нашего модуля

Нам часто приходится сталкиваться с сетью, созданной на заказ и работающей под управлением проприетарного кода для обслуживания клиентов во время конкретных проверок. Большинство имеющихся у нас модулей даже не способны проникнуть в её периметр, и мы не можем корректно просканировать и задокументировать цель с помощью имеющихся средств. Именно здесь нам может пригодиться помощь в освоении Ruby и начале написания собственных модулей.

Всю необходимую информацию о программировании на Ruby для Metasploit можно найти на соответствующей странице [документации Metasploit](https://docs.metasploit.com/api/) . От сканеров до других вспомогательных инструментов, от созданных на заказ эксплойтов до портированных — программирование на Ruby для этого фреймворка является невероятно полезным навыком.

Пожалуйста, ознакомьтесь с приведенным ниже примером аналогичного модуля, который мы можем использовать в качестве шаблонного кода для переноса нашего эксплойта. Это эксплойт уязвимости [Bludit Directory Traversal Image File Upload Vulnerability](https://www.exploit-db.com/exploits/47699) , который уже импортирован в `msfconsole`. Перед демонстрацией эксплойта ( `POC`) ознакомьтесь со всеми полями, включенными в модуль. Обратите внимание, что в приведенном ниже фрагменте кода не были внесены изменения для соответствия нашему текущему импорту, а это прямой снимок существующего модуля, упомянутого выше. Информация должна быть соответствующим образом скорректирована для нового проекта переноса.

    csrf_token = get_csrf(client, login_url)
    headers = {
      'X-Forwarded-For' => "#{i}-#{password[..4]}",
    }
    data = {
      'tokenCSRF' => csrf_token,
      'username' => username,
      'password' => password,
    }
    puts "[*] Trying password: #{password}"
    auth_res = client.post(login_url, data, headers)
    if auth_ok?(auth_res)
      puts "\n[+] Password found: #{password}"
      break
    end
  end
end
