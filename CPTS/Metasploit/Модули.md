Как мы уже упоминали, Metasploit `modules`— это готовые скрипты со специфическим назначением и соответствующими функциями, которые уже были разработаны и протестированы в реальных условиях. Эта `exploit`категория включает так называемые «доказательства концепции» (proof-of-concept `POCs`), которые можно использовать для эксплуатации существующих уязвимостей в значительной степени автоматизированным способом. Многие часто считают, что неудача эксплойта опровергает существование предполагаемой уязвимости. Однако это лишь доказательство того, что эксплойт Metasploit не работает, а не того, что уязвимости не существует. Это связано с тем, что многие эксплойты требуют настройки под целевые хосты, чтобы они работали. Поэтому автоматизированные инструменты, такие как фреймворк Metasploit, следует рассматривать только как вспомогательный инструмент, а не как замену нашим ручным навыкам.

Оказавшись в меню `msfconsole`, мы можем выбрать из обширного списка, содержащего все доступные модули Metasploit. Каждый из них структурирован в папки, которые будут выглядеть следующим образом:

#### Синтаксис

  Модули

```shell-session
<No.> <type>/<os>/<service>/<name>
```

#### Пример

  Модули

```shell-session
794   exploit/windows/ftp/scriptftp_list
```

#### Номер индекса

Этот `No.`тег будет отображаться для выбора нужного нам эксплойта в процессе поиска. Позже мы увидим, насколько полезен этот `No.`тег для выбора конкретных модулей Metasploit.

#### Тип

Тег `Type`— это первый уровень разделения между модулями Metasploit `modules`. Глядя на это поле, мы можем определить, что будет делать фрагмент кода этого модуля. Некоторые из них , например, `types`не могут `exploit`быть непосредственно использованы в качестве модуля. Однако они предназначены для внедрения структуры наряду с интерактивными элементами для лучшей модульности. Для лучшего понимания, вот возможные типы, которые могут появиться в этом поле:

|**Тип**|**Описание**|
|---|---|
|`Auxiliary`|Возможности сканирования, фаззинга, анализа трафика и администрирования. Дополнительная помощь и функциональность.|
|`Encoders`|Убедитесь, что полезная нагрузка доставлена ​​в пункт назначения в целости и сохранности.|
|`Exploits`|Определяются как модули, использующие уязвимость, которая позволит доставить полезную нагрузку.|
|`NOPs`|(Без кода операции) Обеспечьте одинаковый размер полезной нагрузки при каждой попытке эксплуатации уязвимости.|
|`Payloads`|Код выполняется удалённо и обращается к машине злоумышленника для установления соединения (или получения командной оболочки).|
|`Plugins`|В оценочный процесс можно интегрировать дополнительные сценарии, которые `msfconsole`будут сосуществовать.|
|`Post`|Широкий набор модулей для сбора информации, углубленного анализа и т.д.|

Обратите внимание, что при выборе модуля для доставки полезной нагрузки `use <no.>`команда может использоваться только со следующими модулями, которые могут использоваться в качестве `initiators`(или взаимодействующих) модулей:

|**Тип**|**Описание**|
|---|---|
|`Auxiliary`|Возможности сканирования, фаззинга, анализа трафика и администрирования. Дополнительная помощь и функциональность.|
|`Exploits`|Определяются как модули, использующие уязвимость, которая позволит доставить полезную нагрузку.|
|`Post`|Широкий набор модулей для сбора информации, углубленного анализа и т.д.|

#### ОС

В `OS`теге указывается, для какой операционной системы и архитектуры был создан модуль. Естественно, для разных операционных систем требуется выполнение разного кода для получения желаемых результатов.

#### Услуга

Этот `Service`тег указывает на уязвимую службу, работающую на целевой машине. Для некоторых модулей, таких как `auxiliary`или `post`, этот тег может относиться к более общей операции `gather`, например, к сбору учетных данных.

#### Имя

Наконец, `Name`тег поясняет фактическое действие, которое можно выполнить с помощью этого модуля, созданного для конкретной цели.
