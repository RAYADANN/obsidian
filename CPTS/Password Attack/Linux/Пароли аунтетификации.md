В дистрибутивах Linux поддерживаются различные механизмы аутентификации. Один из наиболее часто используемых — это [подключаемые модули аутентификации (PAM)](https://web.archive.org/web/20220622215926/http://www.linux-pam.org/Linux-PAM-html/Linux-PAM_SAG.html) . Модули, отвечающие за эту функциональность, такие как `pam_unix.so`или `pam_unix2.so`, обычно находятся в каталоге `/usr/lib/x86_64-linux-gnu/security/`в системах на основе Debian. Эти модули управляют информацией о пользователях, аутентификацией, сессиями и изменением паролей. Например, когда пользователь меняет свой пароль с помощью команды `passwd`, вызывается PAM, который принимает соответствующие меры для обработки и хранения информации.

Модуль `pam_unix.so`использует стандартизированные вызовы API из системных библиотек для обновления информации об учетных записях. Основные файлы, из которых он читает и в которые записывает данные, — это `/etc/passwd`и `/etc/shadow`. PAM также включает в себя множество других сервисных модулей, таких как модули для LDAP, операций монтирования и аутентификации Kerberos.

## файл passwd

Файл `/etc/passwd`содержит информацию о каждом пользователе системы и доступен для чтения всем пользователям и службам. Каждая запись в файле соответствует одному пользователю и состоит из полей `seven fields`, которые хранят данные о пользователе в структурированном формате. Эти поля разделены двоеточиями ( `:`). Таким образом, типичная запись может выглядеть примерно так:

  Процесс аутентификации Linux

```shell-session
htb-student:x:1000:1000:,,,:/home/htb-student:/bin/bash
```

|Поле|Ценить|
|---|---|
|Имя пользователя|`htb-student`|
|Пароль|`x`|
|ID пользователя|`1000`|
|Идентификатор группы|`1000`|
|[ГЕКОС](https://en.wikipedia.org/wiki/Gecos_field)|`,,,`|
|Главная страница|`/home/htb-student`|
|Оболочка по умолчанию|`/bin/bash`|

Наиболее важным для наших целей является поле `Password`, поскольку оно может содержать записи различных типов. В редких случаях (как правило, в очень старых системах) это поле может содержать фактический хеш пароля. Однако в современных системах хеши паролей хранятся в файле `/etc/shadow`, который мы рассмотрим позже. Несмотря на это, `/etc/passwd`файл доступен для чтения всем пользователям, что дает злоумышленникам возможность взломать пароли, если хеши хранятся в нем.

Обычно в этом поле содержится значение `x`, указывающее на то, что пароли хранятся в хешированном виде внутри `/etc/shadow`файла. Однако может случиться и так, что файл по ошибке доступен для записи. В этом случае мы сможем полностью `/etc/passwd`удалить поле для пароля пользователя .`root`

  Процесс аутентификации Linux

```shell-session
MuraMitchi@htb[/htb]$ head -n 1 /etc/passwd

root::0:0:root:/root:/bin/bash
```

В результате при попытке входа в систему под этим именем запрос пароля не отображается `root`.

  Процесс аутентификации Linux

```shell-session
MuraMitchi@htb[/htb]$ su

root@htb[/htb]#
```

Хотя описанные сценарии встречаются редко, нам все же следует проявлять бдительность и следить за потенциальными уязвимостями в системе безопасности, поскольку существуют приложения, требующие определенных разрешений для целых папок. Если у администратора мало опыта работы с Linux (или с приложениями и их зависимостями), он может по ошибке назначить права на запись в `/etc`каталог и не исправить это позже.

## Теневой файл

Поскольку чтение хэшей паролей может поставить под угрозу всю систему, `/etc/shadow`был введен этот файл. Он имеет схожий формат с файлом `/etc/passwd`, но отвечает исключительно за хранение и управление паролями. Он содержит всю информацию о паролях для созданных пользователей. Например, если в файле нет записи `/etc/shadow`для пользователя, указанного в файле `/etc/passwd`, этот пользователь считается недействительным. `/etc/shadow`Файл также доступен для чтения только пользователям с административными привилегиями. Формат этого файла разделен на следующие категории `nine fields`:

  Процесс аутентификации Linux

```shell-session
htb-student:$y$j9T$3QSBB6CbHEu...SNIP...f8Ms:18955:0:99999:7:::
```

|Поле|Ценить|
|---|---|
|Имя пользователя|`htb-student`|
|Пароль|`$y$j9T$3QSBB6CbHEu...SNIP...f8Ms`|
|Последнее изменение|`18955`|
|Минимальный возраст|`0`|
|Максимальный возраст|`99999`|
|Предупредительный период|`7`|
|Период бездействия|`-`|
|Дата окончания срока|`-`|
|Зарезервированное поле|`-`|

Если `Password`поле содержит символ, например `!`, или `*`, пользователь не сможет войти в систему, используя пароль Unix. Однако другие методы аутентификации, такие как Kerberos или аутентификация на основе ключей, по-прежнему могут использоваться. То же самое относится и к случаю, когда поле `Password`пустое, то есть для входа в систему пароль не требуется. Это может привести к тому, что некоторые программы будут блокировать доступ к определенным функциям. Поле `Password`также имеет определенный формат, из которого можно извлечь дополнительную информацию:

- `$<id>$<salt>$<hashed>`

Как мы видим, хешированные пароли разделены на три части. Значение `ID`указывает, какой криптографический алгоритм хеширования был использован, обычно один из следующих:

|ИДЕНТИФИКАТОР|Криптографический хеш-алгоритм|
|---|---|
|`1`|[MD5](https://en.wikipedia.org/wiki/MD5)|
|`2a`|[Рыба-фугу](https://en.wikipedia.org/wiki/Blowfish_\(cipher\))|
|`5`|[SHA-256](https://en.wikipedia.org/wiki/SHA-2)|
|`6`|[SHA-512](https://en.wikipedia.org/wiki/SHA-2)|
|`sha1`|[SHA1crypt](https://en.wikipedia.org/wiki/SHA-1)|
|`y`|[Yescrypt](https://github.com/openwall/yescrypt)|
|`gy`|[Призрак-йескрипт](https://www.openwall.com/lists/yescrypt/2019/06/30/1)|
|`7`|[Scrypt](https://en.wikipedia.org/wiki/Scrypt)|

Во многих дистрибутивах Linux, включая Debian, в качестве алгоритма хеширования по умолчанию используется другой `yescrypt`алгоритм. Однако в более старых системах могут встречаться и другие методы хеширования, которые потенциально могут быть взломаны. Мы обсудим, как работает процесс взлома, чуть позже.

## Opasswd

Библиотека PAM ( `pam_unix.so`) может предотвратить повторное использование пользователями старых паролей. Эти предыдущие пароли хранятся в `/etc/security/opasswd`файле. Для чтения этого файла требуются права администратора (root), при условии, что его права доступа не были изменены вручную.

  Процесс аутентификации Linux

```shell-session
MuraMitchi@htb[/htb]$ sudo cat /etc/security/opasswd

cry0l1t3:1000:2:$1$HjFAfYTG$qNDkF0zJ3v8ylCOrKB0kt0,$1$kcUjWZJX$E9uMSmiQeRh4pAAgzuvkq1
```

Рассматривая содержимое этого файла, мы видим, что он содержит несколько записей для пользователя `cry0l1t3`, разделенных запятой ( `,`). Важная деталь, на которую следует обратить внимание, — это тип использованного хеша. Это связано с тем, что алгоритм `MD5`( `$1$`) значительно проще взломать, чем SHA-512. Это особенно важно при идентификации старых паролей и распознавании шаблонов, поскольку пользователи часто используют похожие пароли в нескольких сервисах или приложениях. Распознавание этих шаблонов может значительно повысить наши шансы на правильное угадывание пароля.

## Взлом учетных данных Linux

Получив root-доступ к машине Linux, мы можем собрать хэши паролей пользователей и попытаться взломать их, используя различные методы для восстановления паролей в открытом виде. Для этого мы можем использовать инструмент под названием [unshadow](https://github.com/pmittaldev/john-the-ripper/blob/master/src/unshadow.c) , который входит в состав John the Ripper (JtR). Он работает путем объединения `passwd`файлов `shadow`в один файл, подходящий для взлома.

  Процесс аутентификации Linux

```shell-session
MuraMitchi@htb[/htb]$ sudo cp /etc/passwd /tmp/passwd.bak 
MuraMitchi@htb[/htb]$ sudo cp /etc/shadow /tmp/shadow.bak 
MuraMitchi@htb[/htb]$ unshadow /tmp/passwd.bak /tmp/shadow.bak > /tmp/unshadowed.hashes
```

Теперь этот "незатененный" файл можно атаковать с помощью JtR или hashcat.

  Процесс аутентификации Linux

```shell-session
MuraMitchi@htb[/htb]$ hashcat -m 1800 -a 0 /tmp/unshadowed.hashes rockyou.txt -o /tmp/unshadowed.cracked
```

**Примечание:** Именно `single crack mode`для такого сценария и был разработан JtR.
