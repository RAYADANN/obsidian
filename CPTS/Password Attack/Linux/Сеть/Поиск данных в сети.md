В современном мире, где безопасность имеет первостепенное значение, большинство приложений разумно используют TLS для шифрования конфиденциальных данных при передаче. Однако не все среды полностью защищены. Устаревшие системы, неправильно настроенные сервисы или тестовые приложения, запущенные без HTTPS, по-прежнему могут приводить к использованию незашифрованных протоколов, таких как HTTP или SNMP. Эти уязвимости предоставляют ценную возможность для злоумышленников. `the chance to hunt for credentials in cleartext network traffic`В этом разделе мы рассмотрим практические методы выявления скрытой информации, такой как имена пользователей и пароли, в распространенных протоколах с открытым текстом с помощью Wireshark. Мы также кратко рассмотрим [Pcredz](https://github.com/lgandx/PCredz) — инструмент, который может быстро сканировать сетевой трафик на наличие таких данных.

В таблице ниже перечислены несколько распространенных протоколов, а также их зашифрованные аналоги. Хотя сейчас чаще встречаются защищенные версии, было время, когда протоколы в открытом виде были широко распространены.

|Незашифрованный протокол|Зашифрованный аналог|Описание|
|---|---|---|
|`HTTP`|`HTTPS`|Используется для передачи веб-страниц и ресурсов через интернет.|
|`FTP`|`FTPS/SFTP`|Используется для передачи файлов между клиентом и сервером.|
|`SNMP`|`SNMPv3 (with encryption)`|Используется для мониторинга и управления сетевыми устройствами, такими как маршрутизаторы и коммутаторы.|
|`POP3`|`POP3S`|Получает электронные письма с почтового сервера и отправляет их локальному клиенту.|
|`IMAP`|`IMAPS`|Осуществляет доступ к электронным письмам и управление ими непосредственно на почтовом сервере.|
|`SMTP`|`SMTPS`|Отправляет электронные письма с клиента на сервер или между почтовыми серверами.|
|`LDAP`|`LDAPS`|Выполняет запросы и изменения в работе служб каталогов, таких как учетные данные пользователей и роли.|
|`RDP`|`RDP (with TLS)`|Обеспечивает удалённый доступ к рабочему столу систем Windows.|
|`DNS (Traditional)`|`DNS over HTTPS (DoH)`|Преобразует доменные имена в IP-адреса.|
|`SMB`|`SMB over TLS (SMB 3.0)`|Обеспечивает совместное использование файлов, принтеров и других ресурсов по сети.|
|`VNC`|`VNC with TLS/SSL`|Позволяет осуществлять графическое удалённое управление другим компьютером.|

## Wireshark

[Wireshark](https://www.wireshark.org/) — это хорошо известный анализатор сетевых пакетов, который предустановлен практически во всех дистрибутивах Linux для тестирования на проникновение. Он обладает мощным [механизмом фильтрации](https://www.wireshark.org/docs/man-pages/wireshark-filter.html) , позволяющим эффективно осуществлять поиск как в реальном, так и в перехваченном сетевом трафике. Некоторые базовые, но полезные фильтры включают:

|Фильтр Wireshark|Описание|
|---|---|
|`ip.addr == 56.48.210.13`|Фильтрует пакеты с определенным IP-адресом.|
|`tcp.port == 80`|Фильтрует пакеты по порту (в данном случае HTTP).|
|`http`|Фильтры для HTTP-трафика.|
|`dns`|Фильтрует DNS-трафик, что полезно для мониторинга разрешения доменных имен.|
|`tcp.flags.syn == 1 && tcp.flags.ack == 0`|Фильтрует SYN-пакеты (используемые в TCP-рукопожатиях), что полезно для обнаружения сканирования или попыток подключения.|
|`icmp`|Фильтрует пакеты ICMP (используемые для команды Ping), что может быть полезно для разведки или решения сетевых проблем.|
|`http.request.method == "POST"`|Фильтры для HTTP POST-запросов. В случае, если POST-запросы отправляются по незашифрованному HTTP-трафику, они могут содержать пароли или другую конфиденциальную информацию.|
|`tcp.stream eq 53`|Фильтры для конкретного TCP-потока. Помогают отслеживать обмен данными между двумя хостами.|
|`eth.addr == 00:11:22:33:44:55`|Фильтрует пакеты, поступающие с определенного MAC-адреса или от него.|
|`ip.src == 192.168.24.3 && ip.dst == 56.48.210.3`|Фильтрует трафик между двумя конкретными IP-адресами. Помогает отслеживать обмен данными между конкретными хостами.|

## Pcredz

[Pcredz](https://github.com/lgandx/PCredz) — это инструмент, который можно использовать для извлечения учетных данных из реального трафика или перехваченных сетевых пакетов. В частности, он поддерживает извлечение следующей информации:

- номера кредитных карт
- Учетные данные POP
- Учетные данные SMTP
- Учетные данные IMAP
- Строки сообщества SNMP
- Учетные данные FTP
- Учетные данные из заголовков HTTP NTLM/Basic, а также из HTTP-форм.
- Хэши NTLMv1/v2 из различных типов трафика, включая DCE-RPC, SMBv1/2, LDAP, MSSQL и HTTP.
- Хэши Kerberos (AS-REQ Pre-Auth etype 23)

Для запуска `Pcredz`можно либо клонировать репозиторий и установить все зависимости, либо использовать предоставленный контейнер Docker, подробно описанный в разделе [«Установка](https://github.com/lgandx/PCredz?tab=readme-ov-file#install) » файла README.
