## Хранилище Windows и Диспетчер учетных данных

[Диспетчер учетных данных](https://learn.microsoft.com/en-us/windows-server/security/windows-authentication/credentials-processes-in-windows-authentication#windows-vault-and-credential-manager) — это функция, встроенная в Windows начиная с [дата начала/начала] `Server 2008 R2`. `Windows 7`Подробная документация о его работе недоступна для публичного ознакомления, но по сути, он позволяет пользователям и приложениям безопасно хранить учетные данные, относящиеся к другим системам и веб-сайтам. Учетные данные хранятся в специальных зашифрованных папках на компьютере в профилях пользователя и системы ( [MITRE ATT&CK](https://attack.mitre.org/techniques/T1555/004/) ):

- `%UserProfile%\AppData\Local\Microsoft\Vault\`
- `%UserProfile%\AppData\Local\Microsoft\Credentials\`
- `%UserProfile%\AppData\Roaming\Microsoft\Vault\`
- `%ProgramData%\Microsoft\Vault\`
- `%SystemRoot%\System32\config\systemprofile\AppData\Roaming\Microsoft\Vault\`

Каждая папка хранилища содержит `Policy.vpol`файл с ключами AES (AES-128 или AES-256), защищенными DPAPI. Эти ключи AES используются для шифрования учетных данных. В более новых версиях Windows для `Credential Guard`дополнительной защиты главных ключей DPAPI используется хранение их в защищенных анклавах памяти ( [безопасность на основе виртуализации](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/oem-vbs) ).

Microsoft часто называет защищенные хранилища `Credential Lockers`(ранее — `Windows Vaults`). Диспетчер учетных данных — это функция/API, доступная пользователю, а фактически зашифрованные хранилища — это папки хранилища/блокировщика. В следующей таблице перечислены два типа хранилищ учетных данных Windows:

|Имя|Описание|
|---|---|
|Веб-учетные данные|Учетные данные, связанные с веб-сайтами и онлайн-аккаунтами. Это хранилище используется Internet Explorer и устаревшими версиями Microsoft Edge.|
|Учетные данные Windows|Используется для хранения токенов авторизации для различных сервисов, таких как OneDrive, а также учетных данных, связанных с пользователями домена, локальными сетевыми ресурсами, сервисами и общими каталогами.|

![Диспетчер учетных данных отображает учетные данные Windows и общие учетные данные с датами изменения. Учетные данные на основе сертификатов отсутствуют.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/CredMan_1.png)

Экспорт хранилищ Windows в файлы возможен `.crd`либо через панель управления, либо с помощью следующей команды. Созданные таким образом резервные копии шифруются паролем, предоставленным пользователем, и могут быть импортированы в другие системы Windows.

  Атака на диспетчер учетных данных Windows

```cmd-session
C:\Users\sadams>rundll32 keymgr.dll,KRShowKeyMgr
```

## Перечисление учетных данных с помощью cmdkey

[С помощью команды cmdkey](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmdkey) можно перечислить учетные данные, хранящиеся в профиле текущего пользователя:

  Атака на диспетчер учетных данных Windows

```cmd-session
C:\Users\sadams>whoami
srv01\sadams

C:\Users\sadams>cmdkey /list

Currently stored credentials:

    Target: WindowsLive:target=virtualapp/didlogical
    Type: Generic
    User: 02hejubrtyqjrkfi
    Local machine persistence

    Target: Domain:interactive=SRV01\mcharles
    Type: Domain Password
    User: SRV01\mcharles
```

Сохраненные учетные данные отображаются в следующем формате:

|Ключ|Ценить|
|---|---|
|Цель|Имя ресурса или учетной записи, для которой предназначены учетные данные. Это может быть имя компьютера, доменное имя или специальный идентификатор.|
|Тип|Тип учетных данных. Распространенные типы — это `Generic`общие учетные данные и `Domain Password`учетные данные для входа в систему пользователей домена.|
|Пользователь|Учетная запись пользователя, связанная с данными учетными данными.|
|Упорство|Некоторые учетные данные указывают, сохраняются ли они постоянно на компьютере; учетные данные, помеченные соответствующим образом, `Local machine persistence`сохраняются после перезагрузки.|

Первые учетные данные в приведенном выше выводе команды `virtualapp/didlogical`— это общие учетные данные, используемые службами учетных записей Microsoft/Windows Live. Случайное имя пользователя — это внутренний идентификатор учетной записи. Эту запись можно игнорировать в наших целях.

Второй тип учетных данных — `Domain:interactive=SRV01\mcharles`это доменные учетные данные, связанные с пользователем SRV01\mcharles. `Interactive`Это означает, что учетные данные используются для интерактивных сеансов входа в систему. Всякий раз, когда мы встречаем такой тип учетных данных, мы можем использовать их `runas`для имитации сохраненного пользователя следующим образом:

  Атака на диспетчер учетных данных Windows

```cmd-session
C:\Users\sadams>runas /savecred /user:SRV01\mcharles cmd
Attempting to start cmd as user "SRV01\mcharles" ...
```

![Командная строка отображает информацию о пользователе и сведения о домене. Выполнена команда "whoami", отображается "srv01\mcharles".](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/CredMan_3.png)
