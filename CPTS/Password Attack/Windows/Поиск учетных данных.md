
### 1. Поиск по содержимому файлов

Самый эффективный способ, если пароль записан в блокноте или конфиге.

PowerShell

```
# Ищет строку "password", "user" или "Inlane" во всех текстовых файлах папки Bob
Get-ChildItem -Path C:\Users\Bob\ -Recurse -Filter *.txt | Select-String -Pattern "password|user|Inlane"

# Поиск по всем файлам (включая .xml, .conf, .ini, .bat, .ps1)
Get-ChildItem -Path C:\Users\Bob\ -Recurse -File | Select-String -Pattern "password|admin|login"
```

### 2. Поиск файлов по названию

Если ты ищешь сам файл с паролями или токенами.

PowerShell

```
# Найти все файлы, в названии которых есть "cred", "pass", "git" или "route"
Get-ChildItem -Path C:\Users\Bob\ -Recurse -Include *cred*,*pass*,*git*,*route*,*secret* -ErrorAction SilentlyContinue
```

### 3. Просмотр истории команд (Золотая жила)

Пользователи часто вводят пароли прямо в консоли при подключении к SSH или базам данных.

PowerShell

```
# Чтение истории команд PowerShell (самый частый способ найти пароли в HTB)
Get-Content $env:APPDATA\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt

# Просмотр истории текущей сессии
Get-History
```

### 4. Поиск в переменных окружения

Токены GitLab и API-ключи часто "живут" здесь.

PowerShell

```
# Показать все переменные окружения (ищи GIT_TOKEN, ACCESS_KEY и т.д.)
Get-ChildItem Env:
```

### 5. Работа с реестром (для WinSCP и прочего)

Если программа хранит данные в реестре, а не в файле.

PowerShell

```
# Поиск сохраненных сессий WinSCP
Get-ItemProperty -Path "HKCU:\Software\Martin Prikryl\WinSCP 2\Sessions\*"

# Поиск по всему реестру пользователя слова "password"
Get-ChildItem HKCU:\ -Recurse -ErrorAction SilentlyContinue | Get-ItemProperty | Out-String -Stream | Select-String "password"
```

### 6. Скрытые файлы и системные папки

Пароли часто прячут в скрытых папках приложений.

PowerShell

```
# Показать все файлы, включая скрытые, в домашней директории (ищи .ssh, .gitconfig, .aws)
ls C:\Users\Bob\ -Force
```

Получив доступ к целевой машине Windows через графический интерфейс или командную строку, включение поиска учетных данных в наш подход может дать значительные преимущества. Поиск учетных данных `Credential hunting`— это процесс выполнения детального поиска по файловой системе и в различных приложениях для обнаружения учетных данных. Чтобы понять эту концепцию, давайте рассмотрим ситуацию. Мы получили доступ к рабочей станции ИТ-администратора под управлением Windows 10 через RDP.

## Поисково-ориентированный

Многие инструменты, доступные нам в Windows, обладают функцией поиска. В наше время функции поиска встроены в большинство приложений и операционных систем, поэтому мы можем использовать это в своих интересах при решении задач. Пользователь мог где-то задокументировать свои пароли в системе. Могут даже существовать стандартные учетные данные, которые можно найти в различных файлах. Было бы разумно основывать наш поиск учетных данных на том, что нам известно об использовании целевой системы. В данном случае мы знаем, что имеем доступ к рабочей станции ИТ-администратора.

`What might an IT admin be doing on a day-to-day basis and which of those tasks may require credentials?`

Мы можем использовать этот вопрос и соображения, чтобы уточнить наш поиск и максимально уменьшить необходимость в случайных предположениях.

#### Ключевые слова для поиска

Независимо от того, получим ли мы доступ к графическому интерфейсу или интерфейсу командной строки, мы знаем, что у нас будут инструменты для поиска, но не менее важно то, что именно мы ищем. Вот несколько полезных ключевых терминов, которые помогут нам найти учетные данные:

- Пароли
- Кодовые фразы
- Ключи
- Имя пользователя
- Учетная запись пользователя
- Кредиты
- Пользователи
- Пароли
- конфигурация
- dbcredential
- dbpassword
- pwd
- Авторизоваться
- Реквизиты для входа

Давайте воспользуемся некоторыми из этих ключевых терминов для поиска на рабочем месте ИТ-администратора.

## Инструменты поиска

#### Поиск Windows

Имея доступ к графическому интерфейсу пользователя, стоит попробовать использовать его `Windows Search`для поиска файлов на целевом устройстве, используя некоторые из упомянутых выше ключевых слов.

![При поиске в Windows по запросу "pass" в системных настройках и связанных параметрах отображается пункт "Изменить пароль".](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/WindowsSearch.png)

По умолчанию поиск будет осуществляться в различных настройках операционной системы и файловой системе на предмет файлов и приложений, содержащих ключевой термин, введенный в строку поиска.

#### ЛаЗанье

Мы также можем использовать сторонние инструменты, такие как [LaZagne,](https://github.com/AlessandroZ/LaZagne) для быстрого обнаружения учетных данных, которые веб-браузеры или другие установленные приложения могут небезопасно хранить. LaZagne состоит из `modules`модулей, каждый из которых нацелен на различное программное обеспечение при поиске паролей. Некоторые из распространенных модулей описаны в таблице ниже:

|Модуль|Описание|
|---|---|
|браузеры|Извлекает пароли из различных браузеров, включая Chromium, Firefox, Microsoft Edge и Opera.|
|чаты|Извлекает пароли из различных приложений для обмена сообщениями, включая Skype.|
|почта|Выполняет поиск паролей в почтовых ящиках, включая Outlook и Thunderbird.|
|память|Извлекает пароли из памяти, нацелен на KeePass и LSASS.|
|системный администратор|Извлекает пароли из конфигурационных файлов различных инструментов системного администрирования, таких как OpenVPN и WinSCP.|
|окна|Извлекает учетные данные, специфичные для Windows, используя секреты LSA, диспетчер учетных данных и другие инструменты.|
|Wi-Fi|Выгружает учетные данные Wi-Fi.|

**Примечание:** Веб-браузеры — одни из самых интересных мест для поиска учетных данных, поскольку многие из них предлагают встроенное хранилище учетных данных. В самых популярных браузерах, таких как `Google Chrome`, `Microsoft Edge`, и `Firefox`, сохраненные учетные данные зашифрованы. Однако в интернете можно найти множество инструментов для расшифровки различных баз данных учетных данных, например, [firefox_decrypt](https://github.com/unode/firefox_decrypt) и [decrypt-chrome-passwords](https://github.com/ohyicong/decrypt-chrome-passwords) . LaZagne поддерживает `35`различные браузеры в Windows.

Было бы полезно хранить [автономную копию](https://github.com/AlessandroZ/LaZagne/releases/) LaZagne на нашем хосте атаки, чтобы мы могли быстро перенести её на целевой сервер. `LaZagne.exe`В этом сценарии нам вполне подойдёт. Мы можем использовать наш RDP-клиент для копирования файла с хоста атаки на целевой сервер. Если мы используем, `xfreerdp`всё, что нам нужно сделать, это скопировать и вставить файл в установленную нами RDP-сессию.

После того, как `LaZagne.exe`файл окажется на целевом устройстве, мы можем открыть командную строку или PowerShell, перейти в каталог, куда он был загружен, и выполнить следующую команду:

  Поиск учетных данных в Windows

```cmd-session
C:\Users\bob\Desktop> start LaZagne.exe all
```

Это запустит LaZagne и включит `all`необходимые модули. Мы можем добавить опцию `-vv`для изучения того, что происходит в фоновом режиме. После нажатия Enter откроется новое окно с результатами.

  Поиск учетных данных в Windows

```cmd-session
|====================================================================|
|                                                                    |
|                        The LaZagne Project                         |
|                                                                    |
|                          ! BANG BANG !                             |
|                                                                    |
|====================================================================|


########## User: bob ##########

------------------- Winscp passwords -----------------

[+] Password found !!!
URL: 10.129.202.51
Login: admin
Password: SteveisReallyCool123

```

Если мы воспользуемся этой `-vv`опцией, мы увидим попытки сбора паролей от всего поддерживаемого LaZagne программного обеспечения. Мы также можем посмотреть на странице GitHub в разделе поддерживаемого программного обеспечения, чтобы увидеть все программы, от которых LaZagne будет пытаться получить учетные данные. Может показаться немного шокирующим, насколько легко получить учетные данные в открытом виде. Во многом это объясняется небезопасным способом хранения учетных данных во многих приложениях.

#### findstr

Мы также можем использовать [команду findstr](https://docs.microsoft.com/en-us/windows-server/administration/windows-commands/findstr) для поиска по шаблонам в файлах различных типов. Учитывая распространенные ключевые слова, мы можем использовать различные варианты этой команды для обнаружения учетных данных на целевом устройстве Windows:

  Поиск учетных данных в Windows

```cmd-session
C:\> findstr /SIM /C:"password" *.txt *.ini *.cfg *.config *.xml *.git *.ps1 *.yml
```

## Дополнительные соображения

Существуют тысячи инструментов и ключевых слов, которые можно использовать для поиска учетных данных в операционных системах Windows. Следует помнить, что выбор инструментов будет зависеть от функциональности компьютера. Если мы используем Windows Server, подход может отличаться от подхода для Windows Desktop. Всегда учитывайте, как используется система, это поможет вам определить, где искать. Иногда мы можем даже найти учетные данные, просматривая и отображая содержимое каталогов в файловой системе во время работы инструментов.

Вот еще несколько мест, которые следует учитывать при поиске учетных данных:

- Пароли в групповой политике в общей папке SYSVOL
- Пароли в скриптах в общей папке SYSVOL
- Пароль в скриптах на общих ресурсах ИТ-системы
- Пароли в `web.config`файлах на компьютерах разработчиков и в общих папках ИТ-ресурсов.
- Пароль в`unattend.xml`
- Пароли в полях описания пользователя или компьютера в Active Directory.
- Базы данных KeePass (если нам удастся угадать или взломать главный пароль)
- Обнаружено в пользовательских системах и общих папках.
- Файлы с именами типа `pass.txt`, `passwords.docx`, `passwords.xlsx`обнаруженные в пользовательских системах, общих папках и [SharePoint.](https://www.microsoft.com/en-us/microsoft-365/sharepoint/collaboration)
