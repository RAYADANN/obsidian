В ходе наших тестов на проникновение в каждой компьютерной сети, с которой мы сталкиваемся, будут установлены службы для управления, редактирования или создания контента. Все эти службы размещаются с использованием определенных прав доступа и назначаются конкретным пользователям. Помимо веб-приложений, к этим службам относятся (но не ограничиваются ими) `FTP`, `SMB`, `NFS`, `IMAP/POP3`, `SSH`, `MySQL/MSSQL`, `RDP`, `WinRM`, `VNC`, `Telnet`, `SMTP`, и `LDAP`.

Для получения более подробной информации о многих из этих услуг ознакомьтесь с модулем [«Создание базы данных»](https://academy.hackthebox.com/course/preview/footprinting) на HTB Academy.

Представим, что мы хотим управлять сервером Windows по сети. Соответственно, нам нужен сервис, который позволит нам получить доступ к системе, выполнять на ней команды или получать доступ к ее содержимому через графический интерфейс или терминал. В этом случае наиболее распространенными подходящими сервисами являются `RDP`, `WinRM`, и `SSH`. SSH не так распространен в Windows, но является ведущим сервисом для систем на базе Linux.

Все эти сервисы используют механизм аутентификации с помощью имени пользователя и пароля. Конечно, эти сервисы можно модифицировать и настроить таким образом, чтобы для входа в систему использовались только предопределенные ключи, но во многих случаях они настроены с использованием параметров по умолчанию.

## WinRM

[Windows Remote Management](https://docs.microsoft.com/en-us/windows/win32/winrm/portal) ( `WinRM`) — это реализация Microsoft [протокола управления веб-службами](https://docs.microsoft.com/en-us/windows/win32/winrm/ws-management-protocol) ( `WS-Management`). Это сетевой протокол, основанный на XML-веб-службах с использованием [протокола Simple Object Access Protocol](https://docs.microsoft.com/en-us/windows/win32/winrm/windows-remote-management-glossary) ( `SOAP`), применяемый для удаленного управления системами Windows. Он обеспечивает связь между [Web-Based Enterprise Management](https://en.wikipedia.org/wiki/Web-Based_Enterprise_Management) ( `WBEM`) и [Windows Management Instrumentation](https://docs.microsoft.com/en-us/windows/win32/wmisdk/wmi-start-page) ( `WMI`), который может вызывать [распределенную компонентную объектную модель](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-dcom/4a893f3d-bd29-48cd-9f43-d9777a4415b0) ( `DCOM`).

В целях безопасности WinRM необходимо активировать и настраивать вручную в Windows 10/11. Поэтому его работа в значительной степени зависит от уровня безопасности в домене или локальной сети, где мы хотим использовать WinRM. В большинстве случаев для повышения безопасности используются сертификаты или только определенные механизмы аутентификации. По умолчанию WinRM использует порты TCP `5985`( `HTTP`) и `5986`( `HTTPS`).

Удобным инструментом для атак на пароли является [NetExec](https://github.com/Pennyw0rth/NetExec) , который также может использоваться для других протоколов, таких как SMB, LDAP, MSSQL и другие. Мы рекомендуем ознакомиться с [официальной документацией](https://www.netexec.wiki/) к этому инструменту, чтобы лучше с ним ознакомиться.

## SSH

[Secure Shell](https://www.ssh.com/academy/ssh/protocol) ( SSH `SSH`) — это более безопасный способ подключения к удалённому хосту для выполнения системных команд или передачи файлов с хоста на сервер. SSH-сервер `TCP port 22`по умолчанию работает на сервере, к которому можно подключиться с помощью SSH-клиента. Эта служба использует три различных криптографических операции/метода: `symmetric`шифрование, `asymmetric`шифрование и `hashing`.

#### Симметричное шифрование

Симметричное шифрование использует ключ `same key`для шифрования и дешифрования. Любой, кто имеет доступ к ключу, может также получить доступ к передаваемым данным. Поэтому для безопасного симметричного шифрования необходима процедура обмена ключами. Для этой цели используется метод [обмена ключами Диффи-Хеллмана](https://en.wikipedia.org/wiki/Diffie%E2%80%93Hellman_key_exchange) . Если третье лицо получит ключ, оно не сможет расшифровать сообщения, поскольку метод обмена ключами неизвестен. Однако это используется сервером и клиентом для определения секретного ключа, необходимого для доступа к данным. Могут использоваться многие различные варианты симметричной системы шифрования, такие как AES, Blowfish, 3DES и т. д.

#### Асимметричное шифрование

Асимметричное шифрование использует `two keys`закрытый и открытый ключи. Закрытый ключ должен оставаться секретным, поскольку только он может расшифровать сообщения, зашифрованные открытым ключом. Если злоумышленник получит закрытый ключ, который часто не защищен паролем, он сможет войти в систему без учетных данных. После установления соединения сервер использует открытый ключ для инициализации и аутентификации. Если клиент может расшифровать сообщение, он получает закрытый ключ, и сеанс SSH может начаться.

#### Хэширование

Метод хеширования преобразует передаваемые данные в другое уникальное значение. SSH использует хеширование для подтверждения подлинности сообщений. Это математический алгоритм, работающий только в одном направлении.

## Протокол удалённого рабочего стола (RDP)

[Протокол удаленного рабочего стола](https://docs.microsoft.com/en-us/troubleshoot/windows-server/remote/understanding-remote-desktop-protocol) ( RDP) от Microsoft `RDP`— это сетевой протокол, который `TCP port 3389`по умолчанию обеспечивает удаленный доступ к системам Windows. RDP предоставляет как пользователям, так и администраторам/специалистам поддержки удаленный доступ к хостам Windows внутри организации. Протокол удаленного рабочего стола определяет двух участников для подключения: так называемый терминальный сервер, на котором выполняется фактическая работа, и терминальный клиент, через который терминальный сервер управляется удаленно. Помимо обмена изображениями, звуком, данными с клавиатуры и указательного устройства, RDP также может печатать документы терминального сервера на принтере, подключенном к терминальному клиенту, или предоставлять доступ к имеющимся на нем носителям информации. Технически, RDP является протоколом прикладного уровня в стеке IP и может использовать TCP и UDP для передачи данных. Протокол используется различными официальными приложениями Microsoft, а также некоторыми решениями сторонних разработчиков.

## МСП

[](https://docs.microsoft.com/en-us/windows/win32/fileio/microsoft-smb-protocol-and-cifs-protocol-overview)`SMB`Протокол [Server Message Block](https://docs.microsoft.com/en-us/windows/win32/fileio/microsoft-smb-protocol-and-cifs-protocol-overview) ( SMB) отвечает за передачу данных между клиентом и сервером в локальных сетях. Он используется для реализации совместного доступа к файлам и каталогам, а также для служб печати в сетях Windows. SMB часто называют файловой системой, но это не так. SMB можно сравнить с протоколом `NFS`для Unix и Linux, предназначенным для предоставления доступа к дискам в локальных сетях.

SMB также известен как [Common Internet File System](https://cifs.com/) ( Common Internet File System `CIFS`). Он является частью протокола SMB и обеспечивает универсальное удалённое подключение к различным платформам, таким как Windows, Linux или macOS. Кроме того, мы часто будем сталкиваться с [Samba](https://wiki.samba.org/index.php/Main_Page) , которая является реализацией вышеуказанных функций с открытым исходным кодом. Для SMB мы также можем `hydra`снова использовать Samba, чтобы попробовать разные имена пользователей в сочетании с разными паролями.
