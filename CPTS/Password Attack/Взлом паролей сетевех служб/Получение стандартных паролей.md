## Распыление паролей

[Перебор паролей](https://owasp.org/www-community/attacks/Password_Spraying_Attack) — это тип атаки методом перебора, при котором злоумышленник пытается использовать один и тот же пароль для множества различных учетных записей пользователей. Этот метод может быть особенно эффективен в средах, где пользователи инициализируются с помощью стандартного пароля. Например, если известно, какой пароль администраторы в определенной компании обычно используют `ChangeMe123!`при создании новых учетных записей, целесообразно перебрать этот пароль для всех учетных записей пользователей, чтобы выявить те, которые не были обновлены.

В зависимости от целевой системы для проведения атак методом перебора паролей могут использоваться различные инструменты. Для веб-приложений эффективным вариантом является [Burp Suite](https://portswigger.net/burp) , а для сред Active Directory обычно используются такие инструменты, как [NetExec](https://github.com/Pennyw0rth/NetExec) или [Kerbrute .](https://github.com/ropnop/kerbrute)

  Распыление, заполнение и стандартные настройки

```shell-session
MuraMitchi@htb[/htb]$ netexec smb 10.100.38.0/24 -u <usernames.list> -p 'ChangeMe123!'
```

## подбор учетных данных

[Атака с подбором учетных данных](https://owasp.org/www-community/attacks/Credential_stuffing) — это еще один тип атаки методом перебора, при котором злоумышленник использует украденные учетные данные из одной службы для попытки доступа к другим. Поскольку многие пользователи повторно используют свои имена пользователей и пароли на нескольких платформах (таких как электронная почта, социальные сети и корпоративные системы), такие атаки иногда оказываются успешными. Как и в случае с перебором паролей, подбор учетных данных может осуществляться с помощью различных инструментов, в зависимости от целевой системы. Например, если у нас есть список `username:password`учетных данных, полученных в результате утечки данных из базы данных, мы можем использовать `hydra`следующий синтаксис для выполнения атаки с подбором учетных данных против службы SSH:

  Распыление, заполнение и стандартные настройки

```shell-session
MuraMitchi@htb[/htb]$ hydra -C user_pass.list ssh://10.100.38.23
```

## Учетные данные по умолчанию

Многие системы, такие как маршрутизаторы, межсетевые экраны и базы данных, поставляются с учетными данными `default credentials`. Хотя передовая практика предписывает администраторам изменять эти учетные данные во время настройки, иногда они остаются без изменений, что представляет серьезную угрозу безопасности.

Хотя в интернете доступно несколько списков известных учетных данных по умолчанию, существуют также специальные инструменты, автоматизирующие этот процесс. Одним из широко используемых примеров является шпаргалка [по учетным данным по умолчанию (Default Credentials Cheat Sheet)](https://github.com/ihebski/DefaultCreds-cheat-sheet) , которую можно установить с помощью команды `pip3``.

  Распыление, заполнение и стандартные настройки

```shell-session
MuraMitchi@htb[/htb]$ pip3 install defaultcreds-cheat-sheet
```

После установки мы можем использовать эту `creds`команду для поиска известных учетных данных по умолчанию, связанных с конкретным продуктом или поставщиком.

  Распыление, заполнение и стандартные настройки

```shell-session
MuraMitchi@htb[/htb]$ creds search linksys

+---------------+---------------+------------+
| Product       |    username   |  password  |

| linksys       |    <blank>    |  <blank>   |
| linksys       |    <blank>    |   admin    |
| linksys       |    <blank>    | epicrouter |
| linksys       | Administrator |   admin    |
| linksys       |     admin     |  <blank>   |
| linksys       |     admin     |   admin    |
| linksys       |    comcast    |    1234    |
```

Помимо общедоступных списков и инструментов, учетные данные по умолчанию часто можно найти в документации к продукту, где обычно описываются шаги, необходимые для настройки службы. Хотя некоторые устройства и приложения запрашивают у пользователя пароль во время установки, другие используют пароль по умолчанию — часто слабый.

Представим, что мы выявили определенные приложения, используемые в сети клиента. После поиска стандартных учетных данных в интернете, мы можем объединить их в новый список, отформатированный как `username:password`, и повторно использовать упомянутую ранее `hydra`команду для попытки доступа.

Помимо приложений, стандартные учетные данные также часто используются в маршрутизаторах. Один из таких списков доступен [здесь](https://www.softwaretestinghelp.com/default-router-username-and-password-list/) . Хотя вероятность того, что учетные данные маршрутизатора останутся неизменными (поскольку эти устройства имеют решающее значение для сетевой безопасности), ошибки все же случаются. Например, маршрутизаторы, используемые во внутренних тестовых средах, могут оставаться с настройками по умолчанию, и их можно использовать для получения дальнейшего доступа.
