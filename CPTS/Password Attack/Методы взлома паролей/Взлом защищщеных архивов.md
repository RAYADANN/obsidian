Помимо отдельных файлов, мы часто будем сталкиваться с `archives`файлами `compressed files`, защищенными паролем, например, ZIP-архивами.

Представим, что сотрудник административной компании запрашивает у клиента сводку анализа в различных форматах, таких как Excel, PDF, Word, а также соответствующую презентацию. Один из подходов — отправка этих файлов по отдельности. Однако, если распространить этот сценарий на крупную организацию, управляющую множеством проектов одновременно, такой способ передачи файлов может стать громоздким и привести к потере отдельных файлов. В таких случаях сотрудники часто полагаются на архивные файлы, которые позволяют им структурированно организовать необходимые документы (обычно с помощью подпапок), а затем объединить их в один консолидированный файл.

Существует множество типов архивных файлов. К числу наиболее часто встречающихся расширений файлов относятся `tar`, `gz`, `rar`, `zip`, `vmdb/vmx`, `cpt`, `truecrypt`, `bitlocker`, `kdbx`, `deb`, `7z`и `gzip`.

Полный список типов архивных файлов можно найти на [сайте FileInfo](https://fileinfo.com/filetypes/compressed) . Вместо того чтобы вводить их вручную, мы можем запросить данные одной строкой кода, применить необходимые фильтры и сохранить результаты в файл. На момент написания статьи на сайте представлен список `365`типов архивных файлов.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ curl -s https://fileinfo.com/filetypes/compressed | html2text | awk '{print tolower($1)}' | grep "\." | tee -a compressed_ext.txt

.mint
.zhelp

.zst
.apz

.vrpackage

.gzip

.pkg.tar.xz
<SNIP>
```

Следует отметить, что не все типы архивов поддерживают встроенную защиту паролем, и в таких случаях для шифрования файлов часто используются дополнительные инструменты. Например, файлы TAR обычно шифруются с помощью `openssl`или `gpg`.

Учитывая большое разнообразие форматов архивов и инструментов шифрования, в этом разделе мы сосредоточимся только на нескольких методах взлома конкретных типов архивов. Для архивов, защищенных паролем, обычно требуются специальные скрипты для извлечения хешей паролей из файлов, которые затем можно использовать при попытках взлома в автономном режиме.

## Взлом ZIP-файлов

Этот `ZIP`формат часто используется в средах Windows для сжатия множества файлов в один. Процесс взлома зашифрованного ZIP-файла аналогичен тому, что мы уже рассматривали, за исключением использования другого скрипта для извлечения хешей.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ zip2john ZIP.zip > zip.hash
MuraMitchi@htb[/htb]$ cat zip.hash 

ZIP.zip/customers.csv:$pkzip2$1*2*2*0*2a*1e*490e7510*0*42*0*2a*490e*409b*ef1e7feb7c1cf701a6ada7132e6a5c6c84c032401536faf7493df0294b0d5afc3464f14ec081cc0e18cb*$/pkzip2$:customers.csv:ZIP.zip::ZIP.zip
```

После извлечения хеша мы можем использовать JtR для его взлома с помощью нужного списка паролей.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ john --wordlist=rockyou.txt zip.hash

MuraMitchi@htb[/htb]$ john zip.hash --show

ZIP.zip/customers.csv:1234:customers.csv:ZIP.zip::ZIP.zip

1 password hash cracked, 0 left
```

## Взлом зашифрованных файлов GZIP с помощью OpenSSL

Не всегда сразу очевидно, защищен ли файл паролем, особенно если расширение файла соответствует формату, который изначально не поддерживает защиту паролем. Как обсуждалось ранее, `openssl`можно использовать для шифрования файлов в `GZIP`формате. Чтобы определить фактический формат файла, можно использовать команду `file`, которая предоставляет подробную информацию о его содержимом. Например:

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ file GZIP.gzip 

GZIP.gzip: openssl enc'd data with salted password
```

При взломе файлов, зашифрованных с помощью OpenSSL, могут возникать различные проблемы, включая многочисленные ложные срабатывания или полную невозможность определить правильный пароль. Для смягчения этих проблем более надежным подходом является использование инструмента `openssl`в `for`цикле, который пытается напрямую извлечь содержимое, добиваясь успеха только в том случае, если найден правильный пароль.

Следующая однострочная команда может выдать несколько сообщений об ошибках, связанных с GZIP, которые можно смело игнорировать. Если используется правильный список паролей, как в этом примере, мы увидим, что из архива успешно извлечен еще один файл.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ for i in $(cat rockyou.txt);do openssl enc -aes-256-cbc -d -in GZIP.gzip -k $i 2>/dev/null| tar xz;done

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error is not recoverable: exiting now

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error is not recoverable: exiting now
<SNIP>
```

После `for`завершения цикла мы можем проверить текущий каталог на наличие недавно извлеченного файла.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ ls

customers.csv  GZIP.gzip  rockyou.txt
```

## Взлом дисков, зашифрованных с помощью BitLocker.

[BitLocker](https://docs.microsoft.com/en-us/windows/security/information-protection/bitlocker/bitlocker-device-encryption-overview-windows-10) — это функция полного шифрования диска, разработанная Microsoft для операционной системы Windows. Доступная начиная с Windows Vista, она использует `AES`алгоритм шифрования с ключами длиной 128 или 256 бит. Если пароль или PIN-код, использованные для BitLocker, забыты, расшифровку можно выполнить с помощью ключа восстановления — 48-значной строки, сгенерированной в процессе установки.

В корпоративных средах виртуальные диски иногда используются для хранения личной информации, документов или заметок на выданных компанией устройствах, чтобы предотвратить несанкционированный доступ. Для взлома зашифрованного диска BitLocker мы можем использовать скрипт, который генерирует `bitlocker2john`четыре [разных хеша](https://openwall.info/wiki/john/OpenCL-BitLocker) : первые два соответствуют паролю BitLocker, а последние два — ключу восстановления. Поскольку ключ восстановления очень длинный и генерируется случайным образом, его обычно нецелесообразно угадывать — если только нет частичной информации. Поэтому мы сосредоточимся на взломе пароля с помощью первого хеша ( `$bitlocker$0$...`).

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ bitlocker2john -i Backup.vhd > backup.hashes
MuraMitchi@htb[/htb]$ grep "bitlocker\$0" backup.hashes > backup.hash
MuraMitchi@htb[/htb]$ cat backup.hash

$bitlocker$0$16$02b329c0453b9273f2fc1b927443b5fe$1048576$12$00b0a67f961dd80103000000$60$d59f37e70696f7eab6b8f95ae93bd53f3f7067d5e33c0394b3d8e2d1fdb885cb86c1b978f6cc12ed26de0889cd2196b0510bbcd2a8c89187ba8ec54f
```

После генерации хеша для его взлома можно использовать либо , `JtR`либо `hashcat`. В этом примере мы рассмотрим процедуру с `hashcat`. Режим hashcat, связанный с `$bitlocker$0$...`хешем, — `-m 22100`. Мы указываем хеш, задаем список слов и определяем режим хеширования. Поскольку это шифрование использует надежное шифрование AES, взлом может занять значительное время в зависимости от производительности оборудования.

#### Подключение дисков, зашифрованных с помощью BitLocker, в Windows

Самый простой способ смонтировать зашифрованный BitLocker виртуальный диск в Windows — дважды щелкнуть файл `.vhd`. Поскольку он зашифрован, Windows сначала выдаст ошибку. После монтирования просто дважды щелкните том BitLocker, чтобы запросить пароль.

![Проводник файлов отображает папки и диски. BitLocker запрашивает пароль для разблокировки диска E:.](https://cdn.services-k8s.prod.aws.htb.systems/content/modules/308/img/bitlocker.png)

#### Подключение дисков, зашифрованных с помощью BitLocker, в Linux (или macOS)

Также можно монтировать зашифрованные BitLocker диски в Linux (или macOS). Для этого можно использовать инструмент под названием [dislocker](https://github.com/Aorimn/dislocker) . Сначала необходимо установить пакет с помощью команды `apt`:

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ sudo apt-get install dislocker
```

Далее мы создадим две папки, которые будем использовать для монтирования VHD-файла.

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ sudo mkdir -p /media/bitlocker
MuraMitchi@htb[/htb]$ sudo mkdir -p /media/bitlockermount
```

Затем мы используем команду `losetup`для настройки VHD в качестве [зацикленного устройства](https://en.wikipedia.org/wiki/Loop_device) , расшифровываем диск с помощью команды `dislocker`и, наконец, монтируем расшифрованный том:

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ sudo losetup -f -P Backup.vhd
MuraMitchi@htb[/htb]$ sudo dislocker /dev/loop0p2 -u1234qwer -- /media/bitlocker
MuraMitchi@htb[/htb]$ sudo mount -o loop /media/bitlocker/dislocker-file /media/bitlockermount
```

Если все было сделано правильно, теперь мы можем просматривать файлы:

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ cd /media/bitlockermount/
MuraMitchi@htb[/htb]$ ls -la
```

После анализа файлов на смонтированном диске мы можем отмонтировать его, используя следующие команды:

  Взлом защищенных архивов

```shell-session
MuraMitchi@htb[/htb]$ sudo umount /media/bitlockermount
MuraMitchi@htb[/htb]$ sudo umount /media/bitlocker
```
