

DNS выступает в роли интернет-GPS, направляя ваше онлайн-путешествие от запоминающихся ориентиров (доменных имен) к точным числовым координатам (IP-адресам). Подобно тому, как GPS преобразует название пункта назначения в широту и долготу для навигации, DNS преобразует удобочитаемые доменные имена (например `Domain Name System`, ) в числовые IP-адреса (например , ), которые компьютеры используют для связи.`DNS``www.example.com``192.0.2.1`

Представьте, что вам приходится ориентироваться в городе, запоминая точные координаты широты и долготы каждого места, которое вы хотите посетить. Это было бы невероятно громоздко и неэффективно. DNS устраняет эту сложность, позволяя нам использовать легко запоминающиеся доменные имена. Когда вы вводите доменное имя в свой браузер, DNS выступает в роли вашего навигатора, быстро находя соответствующий IP-адрес и направляя ваш запрос к нужному месту в интернете.

Без DNS навигация в интернете была бы сродни вождению автомобиля без карты или GPS — это было бы утомительно и чревато ошибками.

## Как работает DNS

Представьте, что вы хотите посетить веб-сайт, например, такой `www.example.com`. Вы вводите это понятное доменное имя в свой браузер, но ваш компьютер не понимает слов — он говорит на языке чисел, а именно, на языке IP-адресов. Так как же ваш компьютер находит IP-адрес веб-сайта? На помощь приходит DNS, надежный переводчик интернета.

1. `Your Computer Asks for Directions (DNS Query)`Когда вы вводите доменное имя, ваш компьютер сначала проверяет свою память (кэш), чтобы убедиться, что он помнит IP-адрес с предыдущего посещения. Если нет, он обращается к DNS-серверу, обычно предоставляемому вашим интернет-провайдером (ISP).
2. `The DNS Resolver Checks its Map (Recursive Lookup)`У резолвера также есть кэш, и если он не находит IP-адрес там, он начинает свой путь по иерархии DNS. Сначала он обращается к корневому серверу имен, который подобен библиотекарю интернета.
3. `Root Name Server Points the Way`Корневой сервер не знает точного адреса, но знает, кто его знает — сервер имен верхнего уровня (TLD), отвечающий за окончание домена (например, .com, .org). Он указывает резолверу правильное направление.
4. `TLD Name Server Narrows It Down`Сервер имен верхнего уровня (TLD) подобен региональной карте. Он знает, какой авторитетный сервер имен отвечает за конкретный домен, который вы ищете (например, `example.com`), и отправляет туда резолвер.
5. `Authoritative Name Server Delivers the Address`Авторитетный сервер имен — это конечная точка. Это как почтовый адрес нужного вам веб-сайта. Он хранит правильный IP-адрес и отправляет его обратно в резолвер.
6. `The DNS Resolver Returns the Information`: Резолвер получает IP-адрес и передает его на ваш компьютер. Он также запоминает его на некоторое время (кэширует) на случай, если вы захотите снова посетить веб-сайт в ближайшее время.
7. `Your Computer Connects`Теперь, когда ваш компьютер знает IP-адрес, он может напрямую подключиться к веб-серверу, на котором размещен веб-сайт, и вы можете начать просмотр.

### Файл Hosts

Этот `hosts`файл представляет собой простой текстовый файл, используемый для сопоставления имен хостов с IP-адресами, обеспечивая ручной метод разрешения доменных имен, который обходит процесс DNS. В то время как DNS автоматизирует преобразование доменных имен в IP-адреса, этот `hosts`файл позволяет напрямую и локально переопределять эти параметры. Это может быть особенно полезно для разработки, устранения неполадок или блокировки веб-сайтов.

Файл `hosts`находится в папке `C:\Windows\System32\drivers\etc\hosts`на Windows, а `/etc/hosts`на Linux и MacOS — в папке. Каждая строка в файле имеет следующий формат:

        текст
`<IP Address>    <Hostname> [<Alias> ...]`

Например:

        текст
`127.0.0.1       localhost 192.168.1.10    devserver.local`

Для редактирования `hosts`файла откройте его в текстовом редакторе, используя права администратора/root. Добавьте необходимые записи, а затем сохраните файл. Изменения вступят в силу немедленно и не потребуют перезагрузки системы.

К распространенным примерам использования относится перенаправление домена на локальный сервер для разработки:

        текст
`127.0.0.1       myapp.local`

Проверка подключения путем указания IP-адреса:

        текст
`192.168.1.20    testserver.local`

или блокировка нежелательных веб-сайтов путем перенаправления их доменов на несуществующий IP-адрес:

        текст
`0.0.0.0       unwanted-site.com`

### Это как эстафета.

Представьте себе процесс DNS как эстафету. Ваш компьютер начинает с доменного имени и передает его резолверу. Затем резолвер передает запрос корневому серверу, серверу верхнего уровня и, наконец, авторитетному серверу, каждый из которых приближается к цели. Как только IP-адрес найден, он передается обратно по цепочке на ваш компьютер, позволяя вам получить доступ к веб-сайту.

### Основные понятия DNS

В скобках `Domain Name System`( `DNS`), a `zone`— это отдельная часть пространства имен домена, которой управляет конкретная организация или администратор. Представьте это как виртуальный контейнер для набора доменных имен. Например, `example.com`и все его поддомены (такие как `mail.example.com`или `blog.example.com`) обычно принадлежат одной и той же DNS-зоне.

Файл зоны, текстовый файл, расположенный на DNS-сервере, определяет записи ресурсов (о которых речь пойдет ниже) в этой зоне, предоставляя важную информацию для преобразования доменных имен в IP-адреса.

Для наглядности приведем упрощенный пример того, как `example.com`может выглядеть файл зоны:

        dns-zone
`$TTL 3600 ; Default Time-To-Live (1 hour) @       IN SOA   ns1.example.com. admin.example.com. (                 2024060401 ; Serial number (YYYYMMDDNN)                3600       ; Refresh interval                900        ; Retry interval                604800     ; Expire time                86400 )    ; Minimum TTL @       IN NS    ns1.example.com. @       IN NS    ns2.example.com. @       IN MX 10 mail.example.com. www     IN A     192.0.2.1 mail    IN A     198.51.100.1 ftp     IN CNAME www.example.com.`

В этом файле определяются авторитетные серверы имен ( `NS`записи), почтовый сервер ( `MX`запись) и IP-адреса ( `A`записи) для различных хостов в `example.com`домене.

DNS-серверы хранят различные записи ресурсов, каждая из которых выполняет определенную функцию в процессе разрешения доменных имен. Давайте рассмотрим некоторые из наиболее распространенных концепций DNS:

|Концепция DNS|Описание|Пример|
|---|---|---|
|`Domain Name`|Удобочитаемая метка для веб-сайта или другого интернет-ресурса.|`www.example.com`|
|`IP Address`|Уникальный числовой идентификатор, присваиваемый каждому устройству, подключенному к интернету.|`192.0.2.1`|
|`DNS Resolver`|Сервер, который преобразует доменные имена в IP-адреса.|DNS-сервер вашего интернет-провайдера или общедоступные DNS-серверы, такие как Google DNS ( `8.8.8.8`)|
|`Root Name Server`|Серверы верхнего уровня в иерархии DNS.|В мире существует 13 корневых серверов, называемых AM:`a.root-servers.net`|
|`TLD Name Server`|Серверы, отвечающие за конкретные домены верхнего уровня (например, .com, .org).|[Verisign](https://en.wikipedia.org/wiki/Verisign) для `.com`, [PIR](https://en.wikipedia.org/wiki/Public_Interest_Registry) для`.org`|
|`Authoritative Name Server`|Сервер, хранящий фактический IP-адрес домена.|Зачастую управление осуществляется хостинг-провайдерами или регистраторами доменов.|
|`DNS Record Types`|В DNS хранятся различные типы информации.|A, AAAA, CNAME, MX, NS, TXT и т. д.|

Теперь, когда мы рассмотрели основные понятия DNS, давайте углубимся в составляющие элементы информации DNS — различные типы записей. Эти записи хранят различные типы данных, связанных с доменными именами, каждый из которых служит определенной цели:

|Тип записи|Полное имя|Описание|Пример файла зоны|
|---|---|---|---|
|`A`|Адресная запись|Сопоставляет имя хоста с его IPv4-адресом.|`www.example.com.`В А`192.0.2.1`|
|`AAAA`|Запись IPv6-адреса|Сопоставляет имя хоста с его IPv6-адресом.|`www.example.com.`В ААААА`2001:db8:85a3::8a2e:370:7334`|
|`CNAME`|Каноническая запись имени|Создает псевдоним для имени хоста, указывая на другое имя хоста.|`blog.example.com.`В CNAME`webserver.example.net.`|
|`MX`|Запись об обмене почтой|Указывает почтовый сервер(ы), ответственный(е) за обработку электронной почты для домена.|`example.com.`IN MX 10`mail.example.com.`|
|`NS`|Запись сервера имен|Делегирует DNS-зону конкретному авторитетному серверу имен.|`example.com.`В НС`ns1.example.com.`|
|`TXT`|Текстовая запись|Хранит произвольную текстовую информацию, часто используемую для проверки домена или политик безопасности.|`example.com.`В текстовом формате `"v=spf1 mx -all"`(запись SPF)|
|`SOA`|Начало записи о полномочиях|Указывает административную информацию о зоне DNS, включая основной сервер имен, адрес электронной почты ответственного лица и другие параметры.|`example.com.`В СОА`ns1.example.com. admin.example.com. 2024060301 10800 3600 604800 86400`|
|`SRV`|Сервисная книжка|Определяет имя хоста и номер порта для конкретных служб.|`_sip._udp.example.com.`IN SRV 10 5 5060`sipserver.example.com.`|
|`PTR`|Указательная запись|Используется для обратного DNS-запроса, сопоставляя IP-адрес с именем хоста.|`1.2.0.192.in-addr.arpa.`В ПТР`www.example.com.`|

В примерах кавычки " `IN`" обозначают "Интернет". Это поле класса в записях DNS, указывающее на семейство протоколов. В большинстве случаев используется " `IN`", поскольку оно обозначает набор интернет-протоколов (IP), используемый для большинства доменных имен. Существуют и другие значения класса (например, `CH`для Chaosnet, `HS`для Hesiod), но они редко используются в современных конфигурациях DNS.

По сути, " `IN`" — это просто условное обозначение, указывающее на то, что запись относится к стандартным интернет-протоколам, которые мы используем сегодня. Хотя это может показаться дополнительной деталью, понимание её значения позволяет глубже понять структуру DNS-записей.

## Почему DNS важен для веб-разведки

DNS — это не просто технический протокол для преобразования доменных имен; это важнейший компонент инфраструктуры цели, который можно использовать для выявления уязвимостей и получения доступа во время тестирования на проникновение.

- `Uncovering Assets`DNS-записи могут содержать массу информации, включая поддомены, почтовые серверы и записи серверов имен. Например, запись, `CNAME`указывающая на устаревший сервер ( `dev.example.com`CNAME `oldserver.example.net`), может привести к уязвимости системы.
- `Mapping the Network Infrastructure`Анализ данных DNS позволяет создать подробную карту сетевой инфраструктуры целевого объекта. Например, идентификация серверов имен ( `NS`записей) для домена может показать используемого хостинг-провайдера, а `A`запись для — `loadbalancer.example.com`указать на балансировщик нагрузки. Это помогает понять, как связаны различные системы, определить потоки трафика и выявить потенциальные узкие места или уязвимости, которые могут быть использованы при тестировании на проникновение.
- `Monitoring for Changes`Непрерывный мониторинг DNS-записей может выявить изменения в инфраструктуре цели с течением времени. Например, внезапное появление нового поддомена ( `vpn.example.com`) может указывать на новую точку входа в сеть, в то время как `TXT`запись, содержащая значение, подобное , `_1password=...`убедительно свидетельствует о том, что организация использует 1Password, который может быть использован для атак с применением социальной инженерии или целевых фишинговых кампаний.
