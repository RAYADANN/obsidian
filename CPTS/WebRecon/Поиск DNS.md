Получив прочное понимание основ DNS и различных типов записей, перейдем к практике. В этом разделе мы рассмотрим инструменты и методы использования DNS для веб-разведки.

## Инструменты DNS

Разведка DNS включает в себя использование специализированных инструментов, предназначенных для запроса DNS-серверов и извлечения ценной информации. Вот некоторые из наиболее популярных и универсальных инструментов в арсенале специалистов по веб-разведке:

|Инструмент|Основные характеристики|Варианты использования|
|---|---|---|
|`dig`|Универсальный инструмент для поиска DNS-запросов, поддерживающий различные типы запросов (A, MX, NS, TXT и т. д.) и предоставляющий подробный вывод.|Ручные DNS-запросы, передача зон (если разрешено), устранение неполадок DNS и углубленный анализ DNS-записей.|
|`nslookup`|Упрощенный инструмент для поиска DNS-записей, в основном для записей A, AAAA и MX.|Базовые DNS-запросы, быстрая проверка разрешения доменных имен и записей почтового сервера.|
|`host`|Упрощенный инструмент поиска DNS с лаконичным выводом.|Быстрая проверка записей категорий A, AAAA и MX.|
|`dnsenum`|Автоматизированный инструмент для перечисления DNS-запросов, словарные атаки, перебор паролей, передача зон (если разрешено).|Эффективное обнаружение поддоменов и сбор информации DNS.|
|`fierce`|Инструмент для DNS-разведки и перечисления поддоменов с рекурсивным поиском и обнаружением символов подстановки.|Удобный интерфейс для DNS-разведки, идентификации поддоменов и потенциальных целей.|
|`dnsrecon`|Объединяет несколько методов DNS-разведки и поддерживает различные форматы вывода.|Комплексный перебор DNS-записей, идентификация поддоменов и сбор DNS-записей для дальнейшего анализа.|
|`theHarvester`|Инструмент OSINT, собирающий информацию из различных источников, включая DNS-записи (адреса электронной почты).|Сбор адресов электронной почты, информации о сотрудниках и других данных, связанных с доменом, из различных источников.|
|`Online DNS Lookup Services`|Удобный интерфейс для выполнения DNS-запросов.|Быстрый и простой DNS-запрос, удобный в случаях, когда инструменты командной строки недоступны, для проверки доступности домена или получения основной информации.|

## Информационный Групер доменов

Команда `dig`( `Domain Information Groper`) — это универсальная и мощная утилита для запроса DNS-серверов и получения различных типов DNS-записей. Её гибкость, а также подробный и настраиваемый вывод делают её незаменимым инструментом.

### Общие команды для копания

|Командование|Описание|
|---|---|
|`dig domain.com`|Выполняет поиск записи типа A по умолчанию для домена.|
|`dig domain.com A`|Получает IPv4-адрес (запись A), связанный с доменом.|
|`dig domain.com AAAA`|Получает IPv6-адрес (запись AAAA), связанный с доменом.|
|`dig domain.com MX`|Находит почтовые серверы (записи MX), ответственные за данный домен.|
|`dig domain.com NS`|Определяет авторитетные серверы имен для домена.|
|`dig domain.com TXT`|Извлекает все TXT-записи, связанные с доменом.|
|`dig domain.com CNAME`|Получает запись канонического имени (CNAME) для домена.|
|`dig domain.com SOA`|Получает запись о начале полномочий (SOA) для домена.|
|`dig @1.1.1.1 domain.com`|Указывает конкретный сервер имен для запроса; в данном случае 1.1.1.1|
|`dig +trace domain.com`|Отображает полный путь разрешения DNS-запросов.|
|`dig -x 192.168.1.1`|Выполняет обратный поиск по IP-адресу 192.168.1.1 для нахождения соответствующего имени хоста. Возможно, потребуется указать сервер имен.|
|`dig +short domain.com`|Дает краткий и лаконичный ответ на запрос.|
|`dig +noall +answer domain.com`|Отображает только раздел с ответом на запрос.|
|`dig domain.com ANY`|Получает все доступные DNS-записи для домена (Примечание: многие DNS-серверы игнорируют `ANY`запросы для снижения нагрузки и предотвращения злоупотреблений, согласно [RFC 8482](https://datatracker.ietf.org/doc/html/rfc8482) ).|

Внимание: Некоторые серверы могут обнаруживать и блокировать чрезмерное количество DNS-запросов. Будьте осторожны и соблюдайте ограничения по количеству запросов. Всегда получайте разрешение, прежде чем проводить масштабную DNS-разведку целевого объекта.

## Поиск DNS

        shellsession
`MuraMitchi@htb[/htb]$ dig google.com ; <<>> DiG 9.18.24-0ubuntu0.22.04.1-Ubuntu <<>> google.com ;; global options: +cmd ;; Got answer: ;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 16449 ;; flags: qr rd ad; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0 ;; WARNING: recursion requested but not available ;; QUESTION SECTION: ;google.com.                    IN      A ;; ANSWER SECTION: google.com.             0       IN      A       142.251.47.142 ;; Query time: 0 msec ;; SERVER: 172.23.176.1#53(172.23.176.1) (UDP) ;; WHEN: Thu Jun 13 10:45:58 SAST 2024 ;; MSG SIZE  rcvd: 54`

Этот вывод является результатом DNS-запроса, выполненного с использованием `dig`команды для домена `google.com`. Команда была выполнена в системе, работающей под управлением `DiG`версии `9.18.24-0ubuntu0.22.04.1-Ubuntu`. Вывод можно разделить на четыре ключевых раздела:

1. Заголовок
    - `;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 16449`Эта строка указывает тип запроса ( `QUERY`), статус успешного выполнения ( `NOERROR`) и уникальный идентификатор ( `16449`) для данного конкретного запроса.
        - `;; flags: qr rd ad; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 0`Это описание флагов в заголовке DNS:
            - `qr`Флаг ответа на запрос — указывает, что это ответ.
            - `rd`Флаг "Recursion Desired" означает, что запрошена рекурсия.
            - `ad`Флаг «Подлинные данные» означает, что средство разрешения данных считает данные подлинными.
            - Остальные числа указывают количество записей в каждом разделе DNS-ответа: 1 вопрос, 1 ответ, 0 авторитетных записей и 0 дополнительных записей.
    - `;; WARNING: recursion requested but not available`Это означает, что была запрошена рекурсия, но сервер её не поддерживает.
2. Раздел вопросов
    - `;google.com. IN A`Эта строка уточняет вопрос: «Для чего предназначен IPv4-адрес (запись A) `google.com`?»
3. Раздел ответов
    - `google.com. 0 IN A 142.251.47.142`Это ответ на запрос. Он указывает, что связанный с `google.com`ним IP-адрес — `142.251.47.142`. Символ ' `0`' обозначает `TTL`время жизни (time-to-live), показывая, как долго результат может храниться в кэше до обновления.
4. Нижний колонтитул
    - `;; Query time: 0 msec`Здесь показано время, затраченное на обработку запроса и получение ответа (0 миллисекунд).
    - `;; SERVER: 172.23.176.1#53(172.23.176.1) (UDP)`: Это позволяет определить DNS-сервер, предоставивший ответ, и используемый протокол (UDP).
    - `;; WHEN: Thu Jun 13 10:45:58 SAST 2024`Это отметка времени, когда был сделан запрос.
    - `;; MSG SIZE rcvd: 54`Это указывает на размер полученного DNS-сообщения (54 байта).

`opt pseudosection`В запросе иногда может присутствовать исключение `dig`. Это связано с механизмами расширения DNS ( `EDNS`), которые позволяют использовать дополнительные функции, такие как увеличение размера сообщений и `DNSSEC`поддержка расширений безопасности DNS ( ).
