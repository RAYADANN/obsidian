# Отчет по результатам аудита безопасности: Полный захват аккаунта (Account Takeover)

**Объект исследования:** `gameflip.com` / `production-gameflip.fingershock.com` **Дата:** Январь 2026 г. **Исследователь:** [Muramitchi] **Уровень критичности:** **Критический (9.8/10 по шкале CVSS)** **Тип уязвимости:** Нарушение механизмов аутентификации и раскрытие конфиденциальных данных.

---

## 1. Резюме (Executive Summary)

В ходе аудита платформы Gameflip была обнаружена критическая уязвимость в процессе авторизации. Система передает конфиденциальные токены сессии (`access_token`) и персональные данные пользователей (PII) через GET-параметры URL. Это приводит к возможности несанкционированного доступа к чужим аккаунтам (Session Hijacking) и позволяет осуществить полный захват аккаунта (ATO), обходя проверку пароля при обновлении профиля.

## 2. Классификация уязвимостей по стандартам CWE

### 2.1 CWE-598: Использование GET-запроса для передачи конфиденциальных данных

Приложение передает `access_token`, `email` и внутренний идентификатор пользователя в строке запроса URL.

- **Риск:** Параметры URL сохраняются в логах веб-серверов, кэше браузеров и передаются сторонним ресурсам через заголовок `Referer`.
    

### 2.2 CWE-287: Нарушение механизмов аутентификации

Система не проверяет контекст запроса (IP-адрес, User-Agent). Токен, полученный из URL, может быть использован в совершенно другой сессии (например, в режиме инкогнито) для установления авторизованного доступа.

### 2.3 CWE-620: Незащищенная смена пароля

После входа через скомпрометированный токен платформа позволяет изменять **email** и **пароль** аккаунта без ввода текущего пароля. Это позволяет злоумышленнику полностью заблокировать доступ легитимному владельцу.

### 2.4 CWE-1004: Отсутствие флага HttpOnly у чувствительных куки

Сессионная кука `coframe.user.token` не защищена флагом `HttpOnly`. Это делает её доступной для кражи через JavaScript-сценарии (XSS-атаки).

### 2.5. Отсутствие привязки сессии (Session Binding)

- **Наблюдение:** Токен `gf_access_token` не имеет привязки к "отпечатку" браузера (Fingerprint), IP-адресу или конкретной сессии.
- **Доказательство:** Успешно проведена атака методом инъекции токена (Token Injection). Токен, извлеченный из одного браузера, был вручную импортирован в `localStorage` другого браузера, что позволило мгновенно получить доступ к аккаунту без ввода учетных данных.

## 3. Технический анализ и сценарий атаки (PoC)

### Шаг 1: Перехват данных

В процессе авторизации был зафиксирован URL, содержащий критические данные: `https://gameflip.com/login?status=SUCCESS&data[access_token]=tI9WVD6xRPm...&data[signup_profile][email]=user@example.com`
![[Pasted image 20260108064647.png]]
### Шаг 2: Угон сессии (Session Hijacking)

Данный URL был скопирован и открыт в **новом окне режима инкогнито** (где отсутствовали куки и история посещений). Система мгновенно распознала пользователя и предоставила доступ к личному кабинету.

### Шаг 3: Полный захват (Full Takeover)

Находясь в захваченной сессии, исследователь перешел в настройки безопасности. Система позволила сменить пароль и почту без запроса текущего пароля («Current Password»), что подтверждает возможность полной компрометации аккаунта.

## 4. Оценка последствий (Impact)

- **Захват аккаунта:** Полная потеря контроля над профилем для законного владельца.
    
- **Финансовые потери:** Возможность несанкционированного вывода средств из кошелька («Wallet») и совершение фиктивных сделок.
    
- **Утечка данных:** Доступ к личной переписке, истории покупок и персональным данным.
    
- **Репутационный риск:** Высокая вероятность массовых взломов при автоматизации сбора токенов из открытых источников или серверных логов.

## 5. Рекомендации по устранению

### Краткосрочные меры:

1. **Смена метода передачи:** Перейти с GET-запросов на POST-запросы или использовать защищенные callback-механизмы для передачи токенов.
    
2. **Повторная аутентификация:** Внедрить обязательную проверку текущего пароля для любых критических действий (смена почты, пароля, вывод средств).
    
3. **Безопасность куки:** Установить флаги `HttpOnly` и `SameSite=Lax/Strict` для всех сессионных файлов cookie.
    

### Долгосрочные меры:

1. **Стандарты OAuth 2.0:** Привести интеграцию с AWS Cognito в соответствие с современными требованиями безопасности (токены не должны отображаться в адресной строке).
    
2. **Время жизни токенов:** Сделать токены входа одноразовыми с минимальным временем жизни (не более 60 секунд).
