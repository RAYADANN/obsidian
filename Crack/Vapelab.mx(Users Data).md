# Анатомия одного заголовка: Как «лень» разработчика открыла API мексиканского вейп-шопа

Сегодня разберем кейс, который наглядно показывает: безопасность сайта — это не только отсутствие вирусов, но и корректный код. Мы пройдем по шагам от одной маленькой ошибки в HTTP-заголовке до полного раскрытия списка администраторов.

### Шаг 1: Читаем между строк (HTTP Headers)

Исследование любого сайта начинается с анализа ответов сервера. В нашем случае сайт `vapelab.mx` сам выдал свою главную слабость. Взгляните на заголовок ответа в Burp Suite:

`X-Wp-Doingitwrong: register_rest_route (desde 5.5.0; A la definición de ruta de la API REST para vapelab/v1/update-products le falta el argumento permission_callback necesario...)`

Что это значит?

Это системное уведомление WordPress. Разработчик создал кастомный функционал (vapelab/v1), но проигнорировал обязательный аргумент permission_callback.

Вердикт: В системе есть двери, на которые забыли повесить замки. Любой запрос к этому API будет считаться легитимным, даже если у вас нет прав администратора.

Зная "дырявое" пространство имен (`vapelab/v1`), мы отправляемся изучать карту маршрутов. Запрос к корню API (`GET /wp-json/vapelab/v1`) выдает нам JSON со всеми доступными эндпоинтами.

**Самые опасные находки:**

### Шаг 3: User Enumeration — Кто управляет сайтом?

Разработчики, допускающие ошибки в кастомном коде, часто забывают и о стандартной защите. Проверяем эндпоинт пользователей:

GET /wp-json/wp/v2/users

Результат: Сервер послушно отдал список из 11 пользователей.

Из JSON-ответа мы получили:

1. **Реальные логины (slug):** `danacosta`, `seomexico`, `hugo`, `luisdlp`.
    
2. **Привилегии:** Почти все имеют статус `is_super_admin: true`.
    
3. **Личные данные:** Ссылки на аватары Gravatar (через которые можно найти связанные email-адреса) и историю их активности в панели управления.
    

> **Почему это плохо?** Мы выполнили 50% работы для брутфорс-атаки. Теперь нам не нужно гадать "кто" админ, нам нужно только подобрать пароль к уже известным именам.

### Как это исправить? (Советы разработчикам)

1. **Всегда проверяйте права:** В функции `register_rest_route` аргумент `permission_callback` **обязателен**. Используйте `is_user_logged_in()` или `current_user_can('manage_options')`.
    
2. **Отключайте листинг пользователей:** Если ваш сайт не является социальной сетью, закройте доступ к `/wp-json/wp/v2/users` для неавторизованных гостей.
    
3. **Скрывайте ошибки на продакшене:** Заголовки типа `X-Wp-Doingitwrong` не должны попадать к конечному пользователю.

### Дополнение к отчету: Соответствие мировым стандартам безопасности

Чтобы сделать отчет максимально профессиональным, добавим раздел с идентификаторами уязвимостей и их классификацией по базе **MITRE ATT&CK** и **OWASP**.

#### 1. CVE-аналоги для User Enumeration

То, что мы увидели на эндпоинте `/wp-json/wp/v2/users`, является классической проблемой WordPress.

- **Аналог:** **CVE-2017-5487**. Это фундаментальная уязвимость WordPress, позволяющая перечислять пользователей через REST API.
    
- **Почему это в отчете:** Несмотря на то, что проблеме много лет, она до сих пор актуальна для сайтов с неправильной конфигурацией.
    

#### 2. Классификация CWE (Common Weakness Enumeration)

Для кастомных эндпоинтов `vapelab/v1/update-products`, где отсутствует проверка прав, мы используем международную классификацию слабостей:

- **CWE-285: Improper Authorization** (Некорректная авторизация). Это база нашей находки — когда программа предоставляет доступ к ресурсу без проверки полномочий.
    
- **CWE-306: Missing Authentication for Critical Function** (Отсутствие аутентификации для критической функции). Идеально подходит для эндпоинта изменения цен товаров.

### Финальный штрих: Сценарий атаки (Kill Chain)

Для читателей блога можно описать "цепочку смерти", как злоумышленник использует эти CVE/CWE вместе:

1. **Reconnaissance (CWE-209):** С помощью заголовков ошибок находим уязвимый эндпоинт.
    
2. **Weaponization (CVE-2017-5487):** Получаем список логинов администраторов.
    
3. **Exploitation (CWE-306):** Через открытый API вносим изменения в базу товаров или пытаемся подобрать пароль к одному из найденных логинов.

**Вывод:** Безопасность — это процесс. Даже если вы используете популярную CMS вроде WordPress, один некорректно написанный плагин может сделать весь сайт уязвимым.
