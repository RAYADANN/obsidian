### A01:2021 — Broken Access Control (Нарушение контроля доступа)

Сюда теперь входят **IDOR** и **CSRF**. Это ошибки, когда система не может проверить, имеет ли право пользователь выполнять действие.

- **Как найти?**
    
    - **IDOR:** В запросе `GET /api/tickets/555` меняем номер на `556`. Если видим чужой билет — уязвимость есть.
        
    - **CSRF:** Проверить, есть ли в формах (например, смена пароля) уникальный токен. Если его нет, пробуем отправить запрос с другого домена.
        
- **Как эксплуатировать?**
    
    - **Пример (CSRF):** Злоумышленник создает страницу с невидимой формой, которая при открытии отправляет запрос на `bank.com/transfer?to=hacker`. Если жертва залогинена в банке, запрос выполнится от её имени.
        
- **Как исправить?**
    
    - Использовать **Anti-CSRF токены**.
        
    - Внедрить **Attribute-Based Access Control (ABAC)**: проверять не только роль, но и принадлежность объекта пользователю.

### A02:2021 — Cryptographic Failures (Сбои в криптографии)

Все, что касается кражи паролей и данных из-за плохого шифрования.

- **Как найти?**
    
    - Поиск "Hardcoded keys": проверка исходного кода на наличие ключей типа `const API_KEY = "12345"`.
        
    - Проверка протоколов: использование `telnet` или `ftp` вместо `ssh` и `sftp`.
        
- **Как эксплуатировать?**
    
    - **Padding Oracle Attack:** метод подбора зашифрованных данных путем анализа сообщений об ошибках сервера при дешифровке.
        
- **Как исправить?**
    
    - Никогда не хранить пароли в MD5 или SHA1. Использовать **Argon2** или **bcrypt** с "солью".
        
    - Отключать кэширование ответов, содержащих чувствительные данные.

### A03:2021 — Injection (Инъекции)

Сюда теперь включен и **XSS** (Cross-Site Scripting).

- **Как найти?**
    
    - **SQLi:** Ввод `' OR 1=1 --` в поле логина.
        
    - **XSS:** Ввод `<script>alert(document.cookie)</script>` в поле комментария.
        
- **Как эксплуатировать?**
    
    - **Stored XSS:** Хакер оставляет комментарий с вредоносным скриптом. Каждый, кто откроет страницу, отправит свои куки хакеру.
        
- **Как исправить?**
    
    - **Contextual Output Encoding:** для защиты от XSS кодировать спецсимволы (`<` превращается в `&lt;`) перед выводом в браузер.
        
    - Использовать **Prepared Statements** для БД.

### A04:2021 — Insecure Design (Небезопасное проектирование)

Ошибки в "фундаменте" логики приложения.

- **Как найти?**
    
    - Анализ механизмов восстановления пароля: можно ли угадать ответы на "секретные вопросы" (девичья фамилия матери и т.д.)?
        
- **Как эксплуатировать?**
    
    - **Race Condition:** Попытка вывести деньги в двух вкладках браузера одновременно. Если проверка баланса идет до списания в обоих потоках, можно вывести сумму дважды.
        
- **Как исправить?**
    
    - Использовать паттерны проектирования безопасности (Secure Design Patterns) и проводить аудит бизнес-логики.

### A05:2021 — Security Misconfiguration (Манипуляции с конфигурацией)

Сюда входит и **XML External Entity (XXE)**.

- **Как найти?**
    
    - **XXE:** Отправить серверу XML-файл, содержащий ссылку на системный файл: `<!ENTITY xxe SYSTEM "file:///etc/passwd">`.
        
- **Как эксплуатировать?**
    
    - Если сервер парсит XML и не настроен правильно, он вернет содержимое `/etc/passwd` прямо в ответе.
        
- **Как исправить?**
    
    - Отключать обработку внешних сущностей (external entities) в XML-парсерах.
        
    - Удалять неиспользуемые фичи в ПО (например, модули веб-сервера).

### A06:2021 — Vulnerable and Outdated Components (Уязвимые компоненты)

- **Как найти?**
    
    - Анализ заголовков: `X-Powered-By: PHP/5.3.3`. Эта версия PHP древняя и имеет сотни уязвимостей.
        
- **Как эксплуатировать?**
    
    - Использование **RCE (Remote Code Execution)** эксплойтов для конкретной версии библиотеки, найденной на GitHub или Exploit-DB.
        
- **Как исправить?**
    
    - Внедрить **SBOM (Software Bill of Materials)** — полный список всех компонентов для быстрого поиска уязвимых частей при выходе новых CVE.

### A07:2021 — Identification and Authentication Failures (Ошибки аутентификации)

- **Как найти?**
    
    - Проверка "Session Fixation": остается ли ID сессии прежним до и после логина? Если да, хакер может подсунуть свой ID жертве.
        
- **Как эксплуатировать?**
    
    - **Stuffing:** Использование ботнетов для автоматического входа с миллионами пар логин:пароль, украденных из других сервисов.
        
- **Как исправить?**
    
    - Генерировать новый Session ID при каждом входе в систему.
        
    - Использовать безопасные флаги для куки: `HttpOnly` (невидимы для JS) и `Secure` (только через HTTPS).

### A08:2021 — Software and Data Integrity Failures (Целостность данных)

- **Как найти?**
    
    - Проверка процесса CI/CD: можно ли отправить код в репозиторий без проверки (Code Review)?
        
- **Как эксплуатировать?**
    
    - **SolarWinds style attack:** внедрение вредоносного кода в процесс сборки легитимного обновления программы.
        
- **Как исправить?**
    
    - Использовать цифровые подписи для всех артефактов и пакетов.

### A09:2021 — Security Logging and Monitoring Failures (Логирование)

- **Как найти?**
    
    - Анализ глубины логов: записывается ли IP-адрес, время и тип действия? Если пишется только "Error", этого мало для расследования.
        
- **Как эксплуатировать?**
    
    - Хакер очищает логи (Log wiping) или заваливает их мусором (Log flooding), чтобы скрыть свои действия.
        
- **Как исправить?**
    
    - Запретить удаление логов (Append-only). Хранить логи на отдельном сервере.

### A10:2021 — Server-Side Request Forgery (SSRF)

- **Как найти?**
    
    - Поиск функций "импорта": загрузка данных из внешних API или по URL.
        
- **Как эксплуатировать?**
    
    - **Cloud Metadata Attack:** Запрос на `http://169.254.169.254/latest/meta-data/iam/security-credentials/`. Если сервис в AWS, он вернет ключи доступа к облаку.
        
- **Как исправить?**
    
    - Запретить серверу обращаться к внутренней сети (127.0.0.1, 192.168.x.x) на уровне Firewall.
