**API — это «черный ход» в серверную часть**, через который фронтенд (сайт или мобилка) общается с базой данных.

Если в обычном вебе мы тестируем страницы, то в API мы тестируем **эндпоинты** (конечные точки) и то, как они обрабатывают данные.

---

### **1. Типы API: REST vs GraphQL**

Это два главных игрока. У них абсолютно разная философия, а значит, и разные подходы к взлому.

#### **A. REST API (Стандарт)**

Работает по принципу «один адрес — одна задача». Использует стандартные методы HTTP:

- `GET /api/users` — получить список пользователей.
    
- `POST /api/users` — создать пользователя.
    
- `PUT /api/users/123` — обновить данные пользователя №123.
    
- `DELETE /api/users/123` — удалить его.
    

**Вектор атаки:** **Незащищенные методы**. Разработчик может закрыть `GET` авторизацией, но забыть про `DELETE`. Пентестер пробует менять методы (Method Tampering) и смотрит, что произойдет.

#### **B. GraphQL (Новая школа)**

Здесь нет десятков адресов. Есть только один: `/graphql`. Ты отправляешь туда запрос на специальном языке, говоря: «Дай мне только имя и почту пользователя №5».

**Вектор атаки:** **Интроспекция (Introspection)**. Это функция, которая позволяет спросить сервер: «А какие данные ты вообще умеешь выдавать?». Если она включена, хакер получает полную карту базы данных со всеми связями.

### **2. Главные уязвимости API (OWASP API Top 10)**

Помимо уже знакомых нам SQLi и IDOR, у API есть свои специфические «болячки»:

#### **BOLA (Broken Object Level Authorization)**

Это то же самое, что IDOR, но в контексте API. Это уязвимость №1 в мире API.

- **Пример:** Ты запрашиваешь свои сообщения: `GET /api/messages/my`. В ответе видишь `id: 500`.
    
- **Атака:** Пробуешь `GET /api/messages/501`. Если сервер отдает чужое сообщение — это BOLA.
    

#### **Mass Assignment (Массовое назначение)**

Сервер берет весь твой JSON и «запихивает» его в базу без фильтрации.

- **Пример:** При регистрации ты отправляешь: `{"user": "ivan", "pass": "123"}`.
    
- **Атака:** Ты добавляешь поле, которое не должен менять: `{"user": "ivan", "pass": "123", "is_admin": true}`.
    
- **Результат:** Если сервер сохранит это, ты станешь админом.
    

#### **Excessive Data Exposure (Излишнее раскрытие данных)**

API часто отдает «сырые» данные из базы, надеясь, что фронтенд сам их отфильтрует.

- **Пример:** Ты запрашиваешь имя пользователя для отображения в профиле.
    
- **Атака:** Ты смотришь ответ сервера через Burp Suite и видишь, что сервер прислал JSON, где помимо имени лежат `password_hash`, `home_address` и `secret_question`, просто браузер их не показывает.

### **3. Как пентестер «щупает» API?**

1. **Поиск документации:** Хакер ищет файлы типа `swagger.json`, `openapi.yaml` или папку `/v1/`. Часто документация API лежит в открытом доступе для разработчиков, помогая хакеру понять все функции.
    
2. **Фаззинг (Fuzzing):** Перебор скрытых эндпоинтов. Если есть `/api/v1/user`, хакер проверит `/api/v1/admin`, `/api/v1/config`, `/api/v1/debug`.
    
3. **Тестирование логики:** Попытка обмануть API. Например, если в интернет-магазине отправить `{"quantity": -1}`, сервер может случайно прибавить деньги на баланс вместо их списания.

### **4. Инструменты для API**

- **Postman / Insomnia:** Утилиты для удобной отправки запросов к API (аналог браузера, но для «голых» данных).
    
- **Burp Suite:** Куда же без него. Перехватываем запросы из мобильного приложения или сайта и меняем их на лету.
    
- **KiteRunner:** Мощный инструмент специально для поиска скрытых путей API.
