# 02 — Пайплайн обработки видео

> Цель: видеть систему целиком — от пикселей до алерта.

---

## Базовый пайплайн

```
Источник
  → Захват (ingest)
  → Декод
  → Препроцессинг
  → Inference (модель)
  → Постпроцессинг
  → Трекинг / ассоциация
  → Бизнес-логика / правила
  → Действие (alert, DB, API, запись клипа)
```

Каждый этап можно оптимизировать отдельно. Узкое место чаще всего: декод, inference или сеть.

---

## Этапы подробнее

### 1. Источник
- IP-камера (RTSP/ONVIF)
- Файл (mp4, mkv)
- USB / промышленная камера
- SDK вендора / NVR stream

### 2. Захват (ingest)
- Подключение к потоку, буферизация
- Обработка обрывов (reconnect)
- Выбор потока: main / substream (часто аналитика на substream)

### 3. Декод
- H.264 / H.265 → кадры (BGR/RGB/YUV)
- Аппаратный vs программный декод
- Drop frames при перегрузке

### 4. Препроцессинг
- Resize под модель (например 640×640)
- Letterbox / crop / ROI
- Нормализация, цветовое пространство
- Иногда: стабилизация, denoise, деинтерлейс

### 5. Inference
- Детектор / классификатор / сегментатор
- Batch или frame-by-frame
- Устройство: CPU / GPU / NPU / VPU

### 6. Постпроцессинг
- NMS (non-maximum suppression)
- Фильтр по confidence
- Пересчёт координат в исходный кадр

### 7. Трекинг
- Связка детектов между кадрами → track ID
- Сглаживание траекторий
- Обработка occlusions (перекрытий)

### 8. Бизнес-логика
- Пересёк ли линию?
- Сколько времени в зоне?
- Превышен ли порог очереди?
- Дедупликация алертов (не спамить)

### 9. Действие
- Webhook / MQTT / REST
- Запись клипа в VMS
- Dashboard / отчёт
- UI оператора

---

## Real-time vs Offline

| Режим | Требование | Типичный кейс |
|---|---|---|
| Real-time | Низкая latency, стабильный FPS | Охрана, живой подсчёт |
| Near real-time | Секунды допустимы | Ритейл-аналитика |
| Offline / batch | Точность важнее скорости | Расследование, разметка |

---

## Что считать «работающей» системой

Не только «модель угадала», а:
1. Поток не падает
2. Задержка приемлема
3. Ложных тревог терпимо для оператора
4. События доходят до нужной системы
5. Есть мониторинг здоровья пайплайна

---

## Типичные bottlenecks

- Слишком тяжёлая модель на слабом GPU
- Декод всех камер в software
- Аналитика на full HD main stream без нужды
- Синхронная обработка без очередей
- Сеть / диск при записи множества клипов
