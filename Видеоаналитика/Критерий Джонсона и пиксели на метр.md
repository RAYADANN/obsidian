# Критерий Джонсона и пиксели на метр

> Сколько пикселей нужно на объект, чтобы **обнаружить / распознать / идентифицировать**. Практика измерения PPM, в том числе через AutoCAD.

---

## 1. Критерий Джонсона (Johnson’s criteria)

### 1.1. Откуда взялся

В 1950-х **John Johnson** (US Army) исследовал, сколько **разрешаемых штрихов (line pairs)** должно укладываться на минимальный размер цели, чтобы наблюдатель с заданной вероятностью:

- **обнаружил** цель (detection),
- **ориентировал** (orientation — направление/ракурс),
- **распознал** класс (recognition — «это грузовик, не танк»),
- **идентифицировал** конкретику (identification — тип/модель).

Изначально — для **тепловизоров и военного наблюдения**, через **line pairs across the target dimension**, не через «пиксели на метр» IP-камер. Но идея перешла в CCTV как **DORI** и таблицы PPM.

### 1.2. Суть идеи

Чем **выше пространственное разрешение на цели**, тем более тонкую задачу можно решать:

```
мало деталей на объекте  →  только «что-то движется / есть человек»
много деталей            →  лицо, номер, нашивки, судебный разбор
```

Это **не магия нейросети**: если на лице 5 пикселей, «распознавание» — лотерея и маркетинг.

### 1.3. DORI (EN 62676-4) — европейская нормаль CCTV

Часто в паспортах камер:

| Уровень | Смысл | Ориентир (px/m) |
|---|---|---|
| **D**etection | Обнаружить присутствие | ~25 |
| **O**bservation | Характерные детали поведения | ~62.5 |
| **R**ecognition | Определить тип объекта | ~125 |
| **I**dentification | Индивидуальная идентификация | ~250 |

Цифры — **ориентиры для человека-оператора** и проектирования обзора. Под нейросети и конкретный вендор могут сдвигать пороги.

## 2. Рабочая шкала «пиксели на метр» (учебный ряд)

Ниже — шкала из твоего курса (запоминаем как **рабочий норматив** при проектировании):

| PPM (пикселей на метр) | Задача | Что реально ожидаем |
|---|---|---|
| **40** | Наблюдение / detect observation | Видим, что объект есть; грубый класс («человек/авто») слабо |
| **90** | Обнаружение (detection) | Уверенно детектируем объект нужного класса |
| **150** | Распознавание (recognition) | Тип/роль: мужчина/женщина ориентировочно, тип авто, действие грубо |
| **250** | Идентификация (identification) | Лицо/номер в хороших условиях, сравнение с эталоном |
| **500** | Судебная идентификация | Детали для разбора инцидента, выше требования к качеству |
| **1000** | Идеальное распознавание | Запас по детализации, плохой ракурс/сжатие ещё терпимы |

> Сравни с DORI: порядок тот же (десятки → сотни px/m), конкретные числа в курсах и вендорах плавают. В проектах **фиксируй шкалу договора/ТЗ**, чтобы не спорить «у нас 125, у вас 150».

### 2.1. Что такое PPM

**Pixels Per Meter** на плоскости объекта:

\[
\mathrm{PPM} = \frac{\text{число горизонтальных пикселей, покрывающих объект}}{\text{реальная ширина объекта в метрах}}
\]

Или через весь кадр:

\[
\mathrm{PPM} = \frac{W_{\text{кадра в пикселях}}}{W_{\text{сцены в метрах на той же дистанции}}}
\]

Пример: человек шириной ~0.5 м занимает 75 px по ширине →  
PPM = 75 / 0.5 = **150 px/m**.

Для лиц часто говорят не PPM, а **пикселей на лицо** (например 60–100+ px ширины лица) — та же физика.

### 2.2. От чего зависит PPM

```
PPM ↑ если:
  - больше разрешение сенсора (при том же угле обзора)
  - уже угол обзора / больше ФР (приближение)
  - объект ближе к камере

PPM ↓ если:
  - широкий угол «видеть всё»
  - объект далеко
  - сильная дисторсия по краю (эффективно меньше полезных px)
  - цифровое увеличение из уже снятого кадра не создаёт новой информации
```

**Важнейший конфликт проекта:** хочешь и широкий обзор двора, и идентификацию на дальнем заборе — одной камерой часто **нельзя**. Нужна вторая с узким углом / PTZ / оптический зум.

## 3. Связь с критерием Джонсона

Johnson: «N разрешаемых периодов на размер цели».  
CCTV PPM: «сколько пикселей матрицы на метр сцены».

Грубый мост: 1 line pair ≈ 2 пикселя (Найквист), но реальное **оптическое** разрешение объектива + сжатие H.264 меньше «номинала матрицы». Поэтому:

> Паспортные 4K ≠ 4K деталей на заборе. Считай **измеренный** PPM и смотри резкость, не только арифметику мегапикселей.

См. [[Оптика — аберрации и асферика]], [[Кодеки GOP битрейт и FPS]].

## 4. Как измерить пиксели на метр

### 4.1. Быстрый метод без CAD (в кадре)

1. Поставь объект известного размера на нужной дистанции (рейка 1 м, дверь 0.9 м, разметка 2 м).
2. Сними кадр / возьми snapshot из VMS.
3. В любом просмотрщике измерь, сколько **пикселей** занимает эта длина (линейка Photoshop, ImageJ, даже Paint + координаты).
4. PPM = px / метры.

Пример: рейка 1.0 м = 180 px → **180 px/m**.

### 4.2. Через геометрию (если знаешь угол и расстояние)

Приблизительно для малого угла:

\[
W_{\text{сцены}} \approx 2 \cdot D \cdot \tan(\mathrm{FOV}_h / 2)
\]

\[
\mathrm{PPM} \approx \frac{W_{\text{пикселей}}}{W_{\text{сцены}}}
\]

где \(D\) — дистанция до плоскости интереса, \(\mathrm{FOV}_h\) — горизонтальный угол обзора.

Производители дают FOV для ФР и размера матрицы — можно оценить на бумаге до монтажа.

### 4.3. Измерение с помощью AutoCAD — зачем и как

AutoCAD (или NanoCAD / DraftSight) удобен, когда есть **чертёж плана** объекта: камера, стены, зона контроля, дистанции.

#### Задача

Получить: «на линии ворот / у турникета / у полки — какой PPM будет у камеры с разрешением \(W_p \times H_p\) и данным углом».

#### Типовой workflow

**Шаг 1. План в метрах**  
Чертишь план этажа в масштабе 1:1 (единицы — метры) или в мм с понятным масштабом. Ставишь точку камеры, ось взгляда, сектор FOV (два луча на \(\pm \mathrm{FOV}/2\)).

**Шаг 2. Плоскость интереса**  
На дистанции цели проводишь отрезок **поперек** луча зрения — это ширина сцены, которую кадр кроет на этой дальности (хорда сектора).  
Измеряешь длину отрезка командой `DIST` / свойствами — это \(W_{\text{метры}}\).

**Шаг 3. PPM**  
\[
\mathrm{PPM} = W_p / W_{\text{метры}}
\]
где \(W_p\) — горизонтальное разрешение потока, который реально идёт в аналитику (часто substream! — не перепутать с main 4K).

**Шаг 4. Зоны на плане**  
Штрихуешь области:

- где PPM ≥ 250 — зона идентификации;
- ≥ 150 — распознавание;
- ≥ 90 — обнаружение;
- остальное — только обзор.

Это сразу видно заказчику: «здесь лицо не поймаете, нужна вторая камера».

**Шаг 5. Уточнение после монтажа**  
План даёт геометрию. После установки — контрольный снимок с метровой рейкой и правка (реальный ФР, crop, матрица).

#### Полезные приёмы в AutoCAD

| Приём | Зачем |
|---|---|
| Слой `CAMERAS`, `FOV`, `PPM_ZONES` | Не смешивать с архитектурой |
| Блок камеры с атрибутом (модель, W_p, FOV) | Пересчёт при замене камеры |
| `LENGTHEN` / касательные к дуге FOV | Точная ширина на радиусе D |
| Подложка PDF/DWG плана БТИ | Реальные стены |
| Таблица PPM рядом с выноской | Документация для ТЗ |

#### Пример числа

- Камера: 1920 px по горизонтали (аналитический поток)
- На плане ширина сцены у ворот на 18 м: **12.8 м**
- PPM = 1920 / 12.8 ≈ **150 px/m** → по шкале курса — зона **распознавания**, для судебной 500 мало → нужен другой ФР или ближе/вторая камера.

#### Частые ошибки

1. Считали main 3840 px, а аналитика сидит на substream 1280 px → PPM завышен в 3 раза.
2. Мерили ширину сцены не перпендикулярно оси — ошибка геометрии.
3. Игнорировали, что у края кадра дисторсия и объект «мельче» по полезной резкости.
4. Путали px/m с px на объект: для узкого столба 0.1 м при 150 px/m будет всего 15 px — мало для распознавания столба как «объекта интереса».

## 5. Проектирование: алгоритм

```
1. Задача: обнаружение / распознавание / идентификация / суд
2. Выбрать целевой PPM из таблицы курса
3. На плане AutoCAD построить FOV и найти W_метры на линии интереса
4. PPM = W_пикс / W_метры
5. Если PPM < цели → ↑ФР / ближе / выше разрешение потока / вторая камера
6. Проверить оптику, свет, shutter, битрейт (чтобы пиксели не умерли в сжатии)
7. После монтажа — рейка + снимок, фиксация в акте
```

## 6. Связь с видеоаналитикой

| PPM низкий | Модель |
|---|---|
| Может ещё детектировать «person» как пятно | Да, иногда |
| Face recognition / LPR | Нет стабильно |
| Счётчик через линию | Часто да (нужен стабильный детект+трек) |

Детектор обучался на объектах определённого размера в кадре. Слишком мелкие — recall падает. Отсюда требования вендоров: «человек не меньше N px ростом».

---

## Резюме

- **Критерий Джонсона** — сколько разрешения нужно на цель для detection → recognition → identification.
- В IP это стало **PPM / DORI**.
- Учебная шкала: **40 / 90 / 150 / 250 / 500 / 1000** px/m.
- **AutoCAD**: план → FOV → ширина сцены в метрах → PPM = пиксели / метры → зоны на чертеже.
- Считай тот поток, который реально ест аналитика.
