# Этапы видеоаналитики

> Полная структура: что такое VA, из каких этапов состоит конвейер, чем этапы отличаются и как их сравнивать между собой.

---

## 1. Определение видеоаналитики

**Видеоаналитика (Video Analytics, VA)** — автоматическое извлечение **смысла** из видеопотока или архива: объекты, события, метрики, тревоги — без непрерывного зрительного контроля человеком.

Формула:

```
Видеоаналитика = захват видео
               + алгоритмический анализ
               + правила/логика
               + реакция системы (событие, запись, отчёт, интеграция)
```

Не путать:

| Термин | Смысл |
|---|---|---|
| Видеонаблюдение (CCTV/VMS) | Снять, записать, показать оператору |
| Компьютерное зрение (CV) | Методы «понять изображение» |
| Видеоаналитика | **Прикладная система** на базе CV (+ правила, железо, эксплуатация) |

CV — инструментарий. VA — продукт/подсистема безопасности или бизнеса.

Подробнее вводная: [[01 — что такое видеоаналитика]].  
Пайплайн технически: [[02 — пайплайн обработки видео]].

## 3. Этапы аналитического конвейера (детально)

### Этап A — Ingest (приём потока)

**Что:** подключение к RTSP/файлу/SDK, удержание соединения, выбор main/substream.  
**Выход:** сжатый битстрим.  
**Риски:** обрывы, неправильный URL, аналитика на не том профиле (думали 4K — пришёл 720p).

### Этап B — Decode

**Что:** H.264/H.265 → кадры YUV/BGR.  
**Выход:** растр во времени.  
**Риски:** CPU/GPU декодера не хватает → drop frames → дыры в треках.

### Этап C — Preprocess

**Что:** resize, letterbox, ROI crop, нормализация, иногда undistort.  
**Выход:** тензор под модель.  
**Риски:** кривой letterbox → съехавшие координаты боксов; выкинули ROI — объект вне зоны.

### Этап D — Detection / Segmentation / Pose… (восприятие кадра)

**Что:** модель отвечает «что и где на этом кадре».  
**Выход:** список объектов: class, score, bbox (или mask).  
**Сравнение подходов:**

| Подход | Определение | Плюсы | Минусы |
|---|---|---|---|
| Motion / background subtract | Пиксели изменились относительно фона | Дёшево, просто | Тени, качание веток, PTZ ломает |
| Классические признаки + каскады | Haar, HOG+SVM… | Мало ресурсов | Слабо на сложных сценах |
| Deep learning detector | CNN (YOLO…) | Устойчивость, классы | Железо, данные, drift |

Связь: [[Нейросети — персептрон и свёртка]], [[05 — детекция объектов]].

### Этап E — Tracking (связь во времени)

**Что:** присвоить объектам ID между кадрами, построить траектории.  
**Выход:** track_id, path, скорость грубо.  
**Зачем:** подсчёт, line crossing, loitering, «тот же человек».  
**Без трека:** каждый кадр — новые «люди», счётчик врёт.

См. [[06 — трекинг]].

### Этап F — Attribute / secondary inference (опционально)

**Что:** по кропу — ре-ID эмбеддинг, цвет авто, наличие каски, OCR номера, face match.  
**Выход:** атрибуты к track_id.  
**Сравнение:** тяжёлые атрибуты гоняют не на каждом кадре, а раз в N кадров / по триггеру.

### Этап G — Event logic (правила)

**Что:** геозоны, линии, таймеры, пороги плотности, расписания.  
**Выход:** событие бизнес-уровня («вторжение в зону А»).  
**Сравнение rule-based vs learned behavior:**

| | Правила | Модель поведения |
|---|---|---|
| Определение | Явные условия на геометрию/время | Сеть/статистика «аномально» |
| Плюс | Прозрачно, настраиваемо | Ловит нетипичное без ручных зон |
| Минус | Не покрывает всё | Сложнее объяснить, нужны данные |

См. [[07 — классификация событий]].

### Этап H — Decision & action

**Что:** фильтр ложных (cooldown, min score, min duration), отправка в VMS, webhook, клип.  
**Выход:** то, за что платит заказчик.  
**Метрика успеха:** не mAP на COCO, а FAR/час и пропуски на объекте. [[08 — метрики и качество]].

## 4. Другая нарезка этапов — «определение → сравнение» (логическая)

В учебном/продуктовом языке VA часто режут **по смыслу задачи**, не по коду:

### 4.1. Детектирование (Detection)

**Определение:** установить факт наличия объекта/движения в кадре или зоне.  
**Сравнение с соседними:** самый «грубый» уровень; достаточно низкого PPM (~90 по вашей шкале для уверенного обнаружения класса; см. [[Критерий Джонсона и пиксели на метр]]).

### 4.2. Классификация / распознавание типа (Recognition)

**Определение:** отнести объект к классу или подтипу («легковой», «человек», «погрузчик»).  
**Сравнение:** нужно больше деталей на объекте (~150 px/m), чем для голого detection.

### 4.3. Идентификация (Identification)

**Определение:** указать **конкретный** экземпляр (это лицо из базы, этот номер).  
**Сравнение:** максимальные требования к PPM, свету, ракурсу, битрейту (~250+; суд — 500+).

### 4.4. Трекинг и поведение

**Определение:** анализ траектории и временны́х условий.  
**Сравнение:** опирается на стабильный detection; сама по себе «идентичность» между камерами — уже Re-ID (отдельный уровень).

### 4.5. Сводная таблица сравнения смысловых этапов

| Этап | Вопрос | Нужно разрешение | Типичный алгоритм | Типичный выход |
|---|---|---|---|---|
| Детекция | Есть ли объект? | Низкое–среднее | Motion / YOLO | bbox + class |
| Распознавание | Что это за тип? | Среднее | Classifier / detector classes | label |
| Идентификация | Кто/какой именно? | Высокое | Face/LPR/ReID | match id |
| Трекинг | Куда движется? | Как у детекции | SORT/ByteTrack… | trajectory |
| Событие | Нарушено правило? | Зависит | Rules / anomaly | alarm |
| Учёт | Сколько / как долго? | Среднее | tracks + lines | counters |

«Определение» = формулировка вопроса этапа.  
«Сравнение» = чем этап богаче/дороже предыдущего по данным, PPM и сложности модели.

## 5. Где крутится аналитика — сравнение архитектур

| Место | Определение | Плюсы | Минусы |
|---|---|---|---|
| On-camera | Софт в камере | Мало трафика | Слабые модели, закрытость |
| Edge-server | Коробка у объекта | Баланс | Нужно обслуживать |
| Central server | ЦОД/серверная | Мощные GPU | Сеть, стоимость канала |
| Cloud | Облако вендора | Масштаб | Latency, privacy, opex |

См. [[09 — железо и ускорение]].

## 6. End-to-end пример (вторжение в зону)

1. Камера даёт substream H.264 1280×720 @ 15 fps  
2. Декод → кадр  
3. YOLO: person 0.87, bbox  
4. Трекер: id=14, вошёл в полигон «периметр»  
5. Правило: class=person ∧ inside(poly) ∧ duration>0.5s ∧ schedule=ночь  
6. Cooldown 30 с по этой зоне  
7. Событие в VMS + 10 с клип  

Если на шаге 1 битрейт удушил края, на шаге 3 recall падает — аналитика «плохая», хотя модель та же. Система = **все этапы**.

## Резюме

- VA — автоматический смысл из видео + действие.
- Технические этапы: ingest → decode → preprocess → detect → track → (attributes) → rules → action.
- Смысловые этапы: обнаружение → распознавание → идентификация → поведение/учёт.
- Сравнивать этапы нужно по **вопросу**, **требованию к PPM**, **алгоритму** и **цене ошибки**.
