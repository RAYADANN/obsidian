Если модель **OSI** — это теоретический стандарт для обучения, то **TCP/IP** (называемая также стеком протоколов Интернета) — это то, на чем реально построен весь современный мир. Она была разработана министерством обороны США (DoD) и максимально упрощена для практического применения.

Главное отличие: уровни TCP/IP более "толстые" и объединяют функции нескольких уровней OSI.

---

### **1. Структура модели TCP/IP**

Модель состоит из **4 уровней**. Давай разберем их от нижнего к верхнему.

#### **I. Network Access Layer (Уровень сетевого доступа)**

_Аналог в OSI: Physical (L1) + Data Link (L2)._ Этот уровень отвечает за то, как данные физически передаются по среде (кабель, Wi-Fi) и как устройства находят друг друга в одной локальной сети.

- **Протоколы:** Ethernet, Wi-Fi (802.11), ARP.
    
- **Адресация:** MAC-адреса.
    
- **Уязвимости:** ARP-spoofing, перехват Wi-Fi трафика.
    

#### **II. Internet Layer (Сетевой уровень)**

_Аналог в OSI: Network (L3)._ Его задача — маршрутизация пакетов между разными сетями. Он не гарантирует доставку, он просто знает, куда отправить пакет дальше.

- **Протоколы:** **IP** (IPv4, IPv6), ICMP (служебные сообщения типа ping), IGMP.
    
- **Адресация:** IP-адреса.
    
- **Уязвимости:** IP-spoofing, DDoS-атаки на сетевом уровне.

#### **III. Transport Layer (Транспортный уровень)**

_Аналог в OSI: Transport (L4)._ Здесь данные превращаются в "потоки". Этот уровень связывает конкретные приложения на двух узлах.

- **Протоколы:**
    
    - **TCP (Transmission Control Protocol):** Надежный. Перед передачей устанавливает связь ("рукопожатие"), проверяет, дошли ли пакеты, и собирает их в правильном порядке.
        
    - **UDP (User Datagram Protocol):** Быстрый. Просто шлет данные. Если пакет потерялся — ну и ладно (используется в видео и играх).
        
- **Адресация:** Порты (0–65535).
    
- **Уязвимости:** SYN-flood, сканирование портов.
    

#### **IV. Application Layer (Прикладной уровень)**

_Аналог в OSI: Session (L5) + Presentation (L6) + Application (L7)._ Всё, с чем взаимодействует программа или пользователь. Здесь данные имеют понятный вид: текст письма, HTML-код сайта или файл.

- **Протоколы:** HTTP, HTTPS, FTP, DNS, SSH, SMTP.
    
- **Уязвимости:** Весь OWASP Top 10 (инъекции, логические ошибки и т.д.).

### **2. Процесс инкапсуляции (Как данные "одеваются")**

Когда ты отправляешь сообщение в мессенджере, данные проходят сверху вниз:

1. **Application:** Текст "Привет" превращается в HTTP-запрос.
    
2. **Transport:** К запросу добавляется заголовок TCP (номер порта получателя, например 443). Теперь это **Сегмент**.
    
3. **Internet:** Добавляется заголовок IP (IP-адрес сервера). Теперь это **Пакет**.
    
4. **Network Access:** Добавляется заголовок Ethernet (MAC-адрес роутера). Теперь это **Кадр (Frame)**.
    

На другой стороне процесс идет снизу вверх (декапсуляция) — сервер "снимает обертки" одну за другой, пока не увидит текст "Привет".

### **3. Главные различия: TCP vs UDP**

Для пентестера понимание разницы между ними критично при сканировании сети.

| Характеристика      | TCP                                   | UDP                       |
| ------------------- | ------------------------------------- | ------------------------- |
| **Соединение**      | Требуется установка (3-way handshake) | Не требуется              |
| **Надежность**      | Гарантирует доставку                  | Не гарантирует            |
| **Скорость**        | Медленнее (из-за проверок)            | Быстрее                   |
| **Порядок пакетов** | Сохраняет (1, 2, 3...)                | Как придут, так придут    |
| **Примеры**         | Браузер (HTTP), Почта, SSH            | Стриминг, Игры, DNS, VoIP |

### **4. Практика: Что это дает пентестеру?**

Зная TCP/IP, ты понимаешь:

- Если ты хочешь просканировать порты (`nmap`), ты работаешь на **Transport Layer**.
    
- Если ты хочешь перехватить данные соседа в кофейне, ты идешь на **Network Access Layer** (ARP-spoofing).
    
- Если ты хочешь подменить сайт, ты атакуешь DNS на **Application Layer**.


Давай разберем **TCP/IP** на уровне «вскрытия».

## 1. Анатомия TCP-заголовка: Твои рычаги управления

Когда ты отправляешь пакет, ты работаешь с 20-байтовым (минимум) заголовком. Для пентестера критически важны следующие поля:

- **Flags (Флаги):** Не только SYN и ACK. Есть еще **URG** (срочные данные), **PSH** (протолкнуть данные без буферизации), **FIN** (завершение), **RST** (сброс).
    
    - _Пентест-кейс:_ Атака **Xmas Scan** (отправка пакета с флагами FIN, PUSH и URG). Старые системы или криво настроенные фаерволы по-разному реагируют на такой «светящийся как елка» пакет, что позволяет определить тип ОС.
        
- **Window Size (Размер окна):** Определяет, сколько данных клиент готов принять до подтверждения.
    
    - _Пентест-кейс:_ Атаки типа **Sockstress**. Если ты отправишь запрос и укажешь Window Size = 0, сервер будет держать соединение открытым, ожидая, пока ты «освободишься», что быстро исчерпывает ресурсы (RAM/CPU) сервера.
        
- **Options (Опции):** Здесь живут MSS (Maximum Segment Size) и SACK (Selective ACK).

## 2. Глубокий анализ Handshake и состояний

Классический 3-way handshake (SYN -> SYN/ACK -> ACK) — это только начало. Профи смотрит на **состояния сокета**:

- **SYN_RECV:** Состояние сервера после получения SYN. Если завалить сервер SYN-пакетами и не отвечать на SYN/ACK, таблица соединений переполнится (**SYN Flood**).
    
- **TIME_WAIT:** Состояние после закрытия соединения. Большое количество соединений в `TIME_WAIT` может привести к тому, что сервер перестанет принимать новые легитимные запросы.
    
- **Sequence Numbers (ISN):** Каждое соединение начинается с порядкового номера.
    
    - _Пентест-кейс:_ Если генератор ISN предсказуем (старые реализации), злоумышленник может угадать следующий номер и внедрить свой пакет в чужую сессию (**TCP Sequence Prediction Attack**), выполняя команды от имени доверенного IP.

## 3. TCP Fast Open (TFO) и Cookie

Обычно данные передаются только _после_ завершения рукопожатия. TFO (RFC 7413) позволяет вставлять данные (например, HTTP GET) прямо в SYN-пакет, если у клиента есть специальная TFO-cookie от сервера.

- **Для пентестера:** Это способ ускорить атаку или обойти некоторые примитивные IPS, которые ожидают данные только в установленном (ESTABLISHED) соединении.

## 4. Манипуляция IP-уровнем (Слой 3)

TCP едет «внутри» IP, и тут свои хитрости:

- **TTL (Time To Live):** Показывает, через сколько роутеров может пройти пакет.
    
    - _Техника Evasion:_ Отправка пакета с малым TTL, который дойдет до WAF/IDS, но «умрет», не дойдя до конечного сервера. Это позволяет «запутать» систему обнаружения вторжений, показывая ей один контент, в то время как сервер получит другой.
        
- **Fragmentation (Фрагментация):** Огромный IP-пакет можно разбить на мелкие фрагменты.
    
    - _Техника IDS Bypass:_ Некоторые старые IDS не умеют собирать фрагменты обратно для анализа. Ты можешь разбить вредоносный SQL-запрос на 10 мелких IP-пакетов, и они проскочат фильтр по отдельности.
        
- **IP ID:** Идентификатор пакета. По тому, как инкрементируется этот ID, можно проводить **IDLE Scan** (через зомби-хост), чтобы сканировать цель, не раскрывая свой IP.

## 5. Взаимодействие с WAF на уровне L4/L3

WAF обычно работает на L7 (прикладной уровень), но он зависит от того, как L4 (TCP) собрал поток данных.

- **TCP Segmentation Offloading (TSO):** Если WAF и сервер по-разному собирают сегменты TCP, возникает возможность **Desync-атаки**. Ты отправляешь данные так, что WAF видит «безопасный» запрос, а сервер из-за особенностей стека ОС склеивает их в «вредоносный».
