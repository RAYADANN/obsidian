**HTTP (HyperText Transfer Protocol)** — это фундамент всего интернета. Если стек TCP/IP — это рельсы и поезда, то HTTP — это правила погрузки и язык общения между клиентом (браузером) и сервером.

Протокол работает на **прикладном уровне (L7)**. Он текстовый, простой и работает по модели «запрос-ответ».

---

### **1. Анатомия HTTP-запроса (Request)**

Когда ты вводишь адрес в браузере, он формирует текстовое сообщение:

- **Метод (Method):** Что мы хотим сделать?
    
    - `GET` — получить данные (открыть страницу).
        
    - `POST` — отправить данные (логин, форма, загрузка файла).
        
    - `PUT` / `PATCH` — обновить данные.
        
    - `DELETE` — удалить.
        
- **Путь (Path):** К какому ресурсу обращаемся (например, `/index.html`).
    
- **Заголовки (Headers):** Дополнительная информация (какой у нас браузер, какие куки есть).
    
- **Тело (Body):** Данные (только для POST/PUT).
    

---

### **2. Анатомия HTTP-ответа (Response)**

Сервер обрабатывает запрос и возвращает ответ:

- **Код состояния (Status Code):** Главный индикатор успеха.
    
    - `2xx` — Успех (самый частый — `200 OK`).
        
    - `3xx` — Перенаправление (например, `301 Moved Permanently`).
        
    - `4xx` — Ошибка клиента (всем известный `404 Not Found` или `403 Forbidden`).
        
    - `5xx` — Ошибка сервера (`500 Internal Server Error`).
        
- **Заголовки:** Информация о сервере, типе контента (`Content-Type: text/html`) и куки для установки (`Set-Cookie`).
    
- **Тело:** Сам HTML-код, картинка или JSON-данные.
    

---

### **3. Эволюция протокола**

1. **HTTP/1.1:** Стандарт, который жил десятилетиями. Главная проблема — для каждого элемента (картинка, скрипт) нужно было открывать отдельное TCP-соединение или ждать очереди.
    
2. **HTTP/2:** Ввел **мультиплексирование**. Теперь по одному TCP-соединению можно качать много файлов одновременно. Данные стали бинарными, а не текстовыми.
    
3. **HTTP/3 (QUIC):** Работает поверх **UDP**. Решает проблему «затора» (Head-of-line blocking) — если один пакет потерялся, остальные продолжают грузиться.
    

---

### **4. Уязвимости HTTP (Что ищет пентестер)**

Поскольку HTTP — это текст, он подвержен множеству манипуляций:

- **HTTP Parameter Pollution (HPP):** Отправка повторяющихся параметров (`?id=1&id=2`), чтобы запутать логику сервера.
    
- **HTTP Response Splitting:** Внедрение символов переноса строки в заголовки для разделения ответа и внедрения своего контента.
    
- **Insecure Headers:** Отсутствие заголовков безопасности (например, `Content-Security-Policy`), что облегчает проведение XSS-атак.
    
- **Session Hijacking:** Перехват куки сессии в незашифрованном HTTP-трафике.
    

---

### **5. Переход к HTTPS**

Главный минус обычного HTTP — он **не зашифрован**. Любой человек в твоей Wi-Fi сети или провайдер может прочитать всё: пароли, переписку, данные карт.

**HTTPS (HyperText Transfer Protocol Secure)** — это тот же HTTP, но обернутый в слой шифрования **TLS (Transport Layer Security)**.

---

### **6. Инструменты для анализа**

- **Браузер (F12 -> Network):** Твой лучший друг. Показывает все запросы, заголовки и время загрузки.
    
- **Burp Suite / OWASP ZAP:** Позволяют перехватить запрос «на лету», изменить его (например, цену товара или ID пользователя) и отправить на сервер.
    
- **cURL:** Консольная утилита для отправки любых HTTP-запросов. Попробуй: `curl -v http://google.com`.
