# Quick Commands

```bash
# Аудит конфигурации OpenSSH сервера на предмет слабых алгоритмов и устаревших версий
./ssh-audit.py <TARGET_IP>

# Максимально подробный вывод подключения для обнаружения разрешенных методов аутентификации
ssh -v <USER>@<TARGET_IP>

# Принудительное использование аутентификации по паролю (полезно при брутфорсе)
ssh <USER>@<TARGET_IP> -o PreferredAuthentications=password

# Создание локального туннеля (Local Port Forwarding)
# Перенаправляет порт <RPORT> на удаленном хосте через SSH на локальный порт <LPORT>
ssh -L <LPORT>:<TARGET_IP>:<RPORT> <USER>@<TARGET_IP>
```

# Technical Description

Secure Shell (SSH) — это сетевой протокол, который обеспечивает безопасный обмен данными между двумя сетевыми устройствами. Он использует криптографию для аутентификации и шифрования сеансов, как правило, работая на стандартном порту TCP 22. В контексте тестирования на проникновение, SSH-сервисы являются важной целью на стадии **Initial Access** (путем брутфорса учетных данных или эксплуатации уязвимостей в устаревших версиях) и **Persistence/Lateral Movement** (использование туннелирования и перенаправления портов).

> [!info] **SSH-1 vs SSH-2**
> Протокол `SSH-2` значительно превосходит устаревшую и уязвимую к MITM-атакам версию `SSH-1` в плане безопасности, шифрования и стабильности. Современные серверы должны использовать только `SSH-2`.

# Command Breakdown

### `ssh -v`
Команда для установления подробного (verbose) соединения с целью сбора информации.
*   `ssh` — Клиент Secure Shell.
*   `-v` — Увеличивает уровень детализации вывода (verbosity). Полезно для просмотра процесса хендшейка и определения, какие методы аутентификации (`publickey`, `password`, `keyboard-interactive`) разрешены сервером.

### `ssh -o PreferredAuthentications=<METHOD>`
Команда для принудительного использования определенного метода аутентификации.
*   `-o` — Позволяет передать опцию конфигурации, как если бы она была в файле `ssh_config`.
*   `PreferredAuthentications=<METHOD>` — Указывает предпочтительный метод аутентификации, например `password` или `publickey`.

### `ssh-audit`
Инструмент для аудита конфигурации SSH-сервера:
*   `./ssh-audit.py <TARGET_IP>` — Проверяет баннер сервера, используемые алгоритмы обмена ключами (`kex`), алгоритмы хост-ключей (`key`) и шифры (`cipher`), выявляя слабые или устаревшие параметры, что может указывать на потенциальные векторы атаки (например, использование слабых эллиптических кривых или устаревших хеш-алгоритмов, как `ssh-rsa`).

# Cheatsheet Table: Опасные Конфигурации OpenSSH (`sshd_config`)

> [!danger] **Усиление Защиты (Hardening)**
> Всегда отключайте нижеприведенные параметры, если они не требуются, чтобы снизить поверхность атаки. Для повышения безопасности используйте только аутентификацию по открытому ключу (`publickey`).

| Параметр | Описание | Риск для безопасности |
| :--- | :--- | :--- |
| `PasswordAuthentication yes` | Разрешает аутентификацию по паролю. | Открывает возможность для атак методом перебора (Brute Force) при наличии известного имени пользователя. |
| `PermitEmptyPasswords yes` | Разрешает вход без пароля. | Критическая уязвимость: позволяет злоумышленнику войти, если имя пользователя известно, а пароль не установлен. |
| `PermitRootLogin yes` | Разрешает прямое подключение пользователю `root`. | Небезопасно. В случае успешного брутфорса злоумышленник сразу получает максимальные привилегии. Рекомендуется использовать `PermitRootLogin prohibit-password` или `no`. |
| `Protocol 1` | Использует устаревшую версию протокола SSH-1. | Протокол `SSH-1` уязвим к известным атакам, включая MITM. |
| `X11Forwarding yes` | Разрешает переадресацию X11. | Может быть источником уязвимостей (как в OpenSSH 7.2p1) и создает дополнительную поверхность для атаки. |
| `DebianBanner yes` | Отображает специальный баннер при входе. | Может предоставить злоумышленнику дополнительную информацию о версии ОС или дистрибутиве. |
